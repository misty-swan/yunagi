# サードパーティライセンス表記の方針

## 1. 目的

Yunagi が利用するオープンソースソフトウェア（OSS）のライセンス条件を満たし、著作権表示とライセンス本文を利用者が確認できるようにする。

## 2. 方針

1. Rust の依存は `cargo-about` 等、JavaScript の依存はライセンス収集ツールで、ライセンス本文と著作権表示を自動収集する。
2. 収集結果は `THIRD_PARTY_LICENSES.md` としてリリースごとに CI で生成し（ビルド・配布手順書 3章）、アプリの「設定 → このアプリについて」から表示する。収集は Rust が `cargo-about`（`about.toml`）、JavaScript が `pnpm licenses`（配布物に入る依存だけ）。生成物は配布物に同梱した（表示する画面は、まだ無い）。
3. 許可するライセンスの一覧を定め（MIT、Apache-2.0、BSD-2-Clause、BSD-3-Clause、ISC、Zlib、MPL-2.0、BSL-1.0、CDLA-Permissive-2.0、Unicode-3.0。`scripts/release/license-policy.json` の `allowed`）、それ以外が混入した場合は CI で検出して止める（ビルド・配布手順書 3.1）。後ろの 3 つは、MIT・Apache-2.0 と同じ寛容なライセンスとして、2026-11-06 に加えた（YUN-96）。BSL-1.0（Boost）は Windows のクリップボードの依存 `clipboard-win`・`error-code`、CDLA-Permissive-2.0（Mozilla の CA 証明書の一覧の使用許諾）は自動更新が連れてくる `webpki-root-certs`（2026-11-06 時点では、配布する 6 組の target の依存に入らないので、`THIRD_PARTY_LICENSES.md` には載らない。入るようになれば、載せる）、Unicode-3.0 は文字の表を持つ依存が使う。外すと Windows のクリップボードと自動更新が動かなくなる。最終の法的確認は、法務文書の確定版（YUN-106）でまとめて受ける。新しい依存が一覧に無いライセンスを連れてきたときは、オーナーが決めるまで `pending` に置く（ふだんは空。検出は止まる）。決まったら、許可するものを `allowed` へ移し、許可しないものは依存を外して `pending` から消す。
4. GPL・AGPL 系のライセンスを持つ依存は、配布形態への影響を確認するまで採用しない。
5. 同梱するフォント（Inter、UDEV Gothic HS。デザインガイド 4章）のライセンス（SIL OFL）も同じ表記に含める。フォントは依存のパッケージとしてではなくファイルとして同梱する（デザインガイド 4章）。1 の収集ツールと 3 の検出の対象にならないため、同梱してよいフォントはデザインガイド 4章に書いたもの（いずれも OFL-1.1。ファイルと SHA-256 もそこに書く）に限り、CI でファイルとライセンス文書を確かめる（ビルド・配布手順書 3章）。増やすときはデザインガイドに書いてから入れる。表記には、フォントと同じ場所に置いたライセンス文書（著作権表示と OFL の本文）を、生成の際に加える。UDEV Gothic HS は、元になった JetBrains Mono と BIZ UDゴシックの著作権表示も含める（デザインガイド 4章「ノートの等幅」）。

## 3. 未決事項

- Yunagi 本体のソースコードを公開するか、公開する場合のライセンス。非公開とする場合も、配布・Issue・脆弱性報告用の公開リポジトリ（インストールスクリプト、CHANGELOG、SECURITY.md を置く）は別に用意する（ビルド・配布手順書 1章）。
