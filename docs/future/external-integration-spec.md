# 外部ツール連携仕様書（ドラフト）

> 有料機能 A（Linear・Jira 連携、要件 F-15）の検討用ドラフトです。各サービスの API 仕様は実装時に最新の公式ドキュメントで確認します。

## 1. 位置づけ

外部ツールを「元帳」、Yunagi を「今日の作業面」とする。Yunagi はプロジェクト管理ツールにはならず、自分に割り当てられた課題のうち、今日やるものだけを取り込む。

## 2. 対象と認証（案）

| サービス | API | 認証 |
| --- | --- | --- |
| Linear | GraphQL API | OAuth 2.0、または個人 API キー |
| Jira Cloud | REST API | OAuth 2.0（3LO）、または API トークン |

認証情報は OS のキーチェーンに保存する。通信は端末から各サービスへ直接行い、Yunagi のサーバーを経由しない。

## 3. 機能

### 3.1 受信箱

- 自分に割り当てられた未完了の課題を一覧表示する（S-07）。
- 利用者が今日やるものを選んで TODO へ送る。毎日自動ですべてを取り込むことはしない。
- 一覧の取得は、受信箱を開いたときと、15分ごとのバックグラウンド更新で行う（間隔は設定可能）。

### 3.2 取り込んだ TODO

- 課題キー（例：`ENG-123`）、タイトル、現在の状態を表示し、課題へのリンクを開ける。
- 本文は外部のタイトルを初期値とし、Yunagi 側で書き換えても外部には反映しない。

### 3.3 完了の書き戻し

- Yunagi で TODO を完了にしたとき、外部の課題を「完了」とみなす状態へ遷移させる。
- どの状態を完了とみなすかは、サービス（Jira はプロジェクト）ごとに初回に一度だけ設定する。
- 進行中・レビュー中など、完了以外の状態は同期しない。
- 書き戻しに失敗した場合（権限不足、ワークフローの制約など）は、TODO に警告の印を付け、外部で手動完了するよう案内する。
- Yunagi で完了を取り消しても（未完了に戻す）、外部には反映しない。外部の状態を戻す必要があれば、外部で戻すよう案内する（案）。
- オフライン時の書き戻しは順番待ちにし、接続が戻ったときに再試行する。再試行でも失敗したら、上と同じく警告の印を付ける（案）。
- エージェント（MCP・CLI）による完了も同じ規則で書き戻す。ただし、エージェントの `todo` 権限とは別に「外部への書き戻し」の許可を設ける（案）。

### 3.4 障害・詰まりとの紐付け

- 障害に外部の課題（他の人の課題を含む）を紐付けられる。
- 紐付けた課題のリンクと現在の状態を表示する。
- 課題が完了になったら、障害の解消を促す表示を出す。自動では解消しない。

## 4. 持ち越しとの関係

- 外部課題と紐付いた TODO を持ち越す場合、紐付けも引き継ぐ。
- 見直しの選択肢「外部ツールへ戻す」は、本機能が有効で、かつ外部課題と紐付いた TODO にだけ表示する（持ち越し回数のしきい値は設定値、既定3回）。それ以外の TODO には「分割する／やめる」だけを示す。
- 「外部ツールへ戻す」を選ぶと、TODO を今日へ持ち越さずに閉じ（`status=dropped`、`close_reason=returned_external`）、外部の課題はそのままにする。

## 5. 課金

本機能は有料オプションに含める。課金が切れた場合、既存の紐付けは表示のみ残し、取得と書き戻しを停止する。
