## 2. MVP の内訳（目安）

1. 基盤：コア、データモデル、論理日付、自動保存、バックアップ
2. 画面：整理モード、ノートモード、持ち越し、検索パレット、設定、Markdown 書き出し
3. 操作：ショートカット、IME 対応、Vimモード
4. 接続口：ローカル API、CLI、MCP サーバー、権限と変更履歴、`agent setup`
5. 配布：CI、インストールスクリプト、自動更新（Homebrew は v1.0 では出さない。署名を取る時期に再検討する。ビルド・配布手順書 4.3）
6. 公開準備：利用者ガイド（日英）、法務文書、公式サイト、販売ページ

## 4. 価格（2026-11-06 決定。YUN-10）

売れる前に置いた**仮説**である。公開から数か月後に、購入数と問い合わせなどの利用状況を見て見直す（3章の判断基準と同じ時期に、数字を足して決め直す）。

### サポーターライセンス（買い切り・任意）

- 価格：**2,500 円（税込）**。1 回の購入で、以後の版も使える。
- 機能の差は付けない（要件定義書 9章）。買わなくても、全機能を使える。
- 特典：
  1. 有料同期の初年度が半額（有料機能 B ができたときに適用する）。意味は「有料同期を使い始めてから最初の 12 か月分の料金が半額」とする（月額なら、最初の 12 か月が半額）。サポーターのキーだけでは割引にならない：割引は、同期の購入の時点に、購入の記録（同期のサーバー側）で確かめる。購入の記録と、サポーターのキーを買った人との結び付け（アカウントやメールアドレスで照合するなど）は、クラウド同期仕様書で決める（キーの発行の元は販売サービス（第一候補は Polar。要件定義書 9章）なので、照合できる情報がそこから得られるかも、そのとき確かめる。アプリは、キーの確認の応答に入っている購入者の情報を保存しない。UI 設計書 7章）。適用の条件（キーの購入時期の制限、使い始めの期限など）は、クラウド同期仕様書を作るときに決める（それまでは、条件を付けない前提で約束し、変えるときは購入者に告知する）。
  2. 「このアプリについて」にサポーターの表示を出す（記念。機能の差ではない。設計は UI 設計書 7章「ライセンス区分と『このアプリについて』」）。
  3. 機能の制限は付けない。

### 根拠

- 相場（第三者の集計サイトの数字で、公式には未確認。2026-11-06 に見た）：Obsidian の Catalyst（機能差のない支援の買い切り）が 25 ドルから、Sublime Text の個人ライセンスが 99 ドル。機能差を付けない支援なので、後者より前者に近い価格にした。
- 決済の手数料（販売の窓口の第一候補 Polar の料金表。https://polar.sh/docs/fees 。2026-11-12 に確認。要件定義書 9章）：売上 1 件につき 5%＋50 セントで、米国以外で発行されたカードには 1.5% が加わる。固定分があるため、安い価格ほど割合が重い。2,500 円の売上を日本のカードで受けると、約 240 円（約 9.5%）になる（1 ドル 150 円として、6.5% が約 163 円、50 セントが 75 円）。為替と、手数料のかかる額（税込か税抜きか）で変わる。ほかに、受け取りのたびに Stripe の手数料がかかる（受け取りのある月に 2 ドル、1 回の受け取りに 0.25%＋25 セント、通貨の両替に最大 1%）。返金しても、元の手数料は戻らない。
- 消費税の扱いは、Polar の文書に記載が無く、未確認（2026-11-12）。販売の窓口の最終決定の前に、Polar への問い合わせと税理士への相談で確かめる（税込表示ができるか、インボイス、販売者の登録の要否。オーナーの作業。YUN-104。要件定義書 11章）。

利用者に向けた価格の正式な表示は、販売ページと公式サイトの確定版で行う。`docs/legal/` の 3 文書には価格の数字を書かない（ビルド・配布手順書 8.3）。
