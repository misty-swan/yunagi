# Yunagi 要件定義書

Nov 2, 2026 · @Kashima Hiromu

## 1. 概要と目的

Yunagi は、PC画面全体を「その日の仕事ノート1枚」として使う日次の業務整理アプリである。一般公開・販売を前提に、個人の知的労働者が毎日開く道具として設計する。

扱う対象は「今日」に限る。今日やること（TODO）、仕事を止めている要因（障害・詰まり）、1日の振り返りの3つを日付単位で整理する。プロジェクト管理や長期タスク管理は意図的に扱わない。

中心体験は次の循環である。ノートに書き散らす、必要な行だけをTODOや障害へ送る、整理モードで今日の仕事を把握する、終業時に振り返りを書き、未完了TODOを翌日へ持ち越す。

最優先の品質は「軽さ」である。キーボードだけで操作でき、保存を意識させず、作業の流れを止めないことを全要件の判断基準とする。

## 2. 想定ユーザーと利用シーン

主な利用者は、ターミナル操作に慣れたエンジニアや技術職の個人である。会議や依頼が細切れに入り、その日の段取りを自分で組み直す必要がある人を想定する。キーボード中心の操作、ローカル保存、Linux 対応、curl での導入は、この層にとっては欠点ではなく選ぶ理由になる。チームでの共有は前提にしない。

企画職や管理職など非エンジニア層は、MVPでは主対象にしない。有料署名とストア配布へ切り替える段階で対象を広げる。

典型的な1日は次のように進む。始業時にアプリを開くと今日のボードが表示され、前日からの持ち越しTODOが並んでいる。会議に入るとショートカットでノートモードに切り替えてメモを取り、終わったら必要な行だけをTODOや障害へ送って整理モードに戻る。終業時に振り返りを書き、未完了TODOを翌日へ回して閉じる。

PCを常時使う業務が対象で、モバイルでの入力はMVPでは想定しない。

## 3. 提供形態・プラットフォーム（提案）

MVPは Windows、macOS、Linux 向けのデスクトップアプリとして提供する。実装は Tauri のような軽量なクロスプラットフォーム基盤を想定し、3つのOSを同じコードから配布する。

デスクトップを推す理由は3つある。第一に、OS全体で効くグローバルショートカットで、どのアプリからでも即座に Yunagi とノートモードを呼び出せる。ブラウザではこれができず、「流れを止めない」という最重要要件を満たしにくい。第二に、起動が速くオフラインで完全に動くため、軽さを担保しやすい。第三に、画面いっぱいの全画面表示や常駐が自然に実現できる。

| 選択肢 | 長所 | 短所 |
| --- | --- | --- |
| デスクトップ（Tauri等）【推奨】 | グローバルショートカット、高速起動、オフライン、全画面、Linux にも同じコードで対応 | 自動更新の運用が必要。有料の署名を使わない場合はOS警告への配慮が要る |
| Web / PWA | 配布が容易、更新が即時 | グローバルショートカット不可、ブラウザのキー操作と衝突しやすい |
| Electron | 実績が多い | 配布サイズとメモリ消費が大きく、軽さと相反する |

Web版は、同期機能を提供する段階で閲覧用・補助用として検討する。

### インストール方式

有料の開発者登録（Apple Developer Program、Windows のコード署名証明書）を使わず、ターミナルから1行で導入する方式を主とする。macOS と Linux は `curl -fsSL https://getyunagi.com/install.sh | sh`、Windows は PowerShell の `irm https://getyunagi.com/install.ps1 | iex` を想定する。

| OS | 配布物 | 署名・OS警告の扱い |
| --- | --- | --- |
| macOS | .app を含むアーカイブ。Homebrew（tap・Cask）は v1.0 では出さない（署名を取る時期に再検討） | Apple Silicon 向けは無料のアドホック署名が必須。curl で取得したファイルには隔離属性が付かないため、Gatekeeper の警告は通常出ない。ブラウザで手動に取ったファイルには隔離属性が付くので、外す手順を公式サイトのダウンロードのページに案内する |
| Linux | AppImage と tar.gz。.deb は任意 | 署名の義務はない。全配布物のハッシュをまとめた `SHA256SUMS` と、その minisign 署名 `SHA256SUMS.sig`（更新用とは別の配布用鍵）を公開する |
| Windows | NSIS のユーザー単位インストーラー（`Yunagi_<ver>_<arch>-setup.exe`） | PowerShell 経由の取得では SmartScreen 警告が出にくいが、完全な回避は保証されない |

アプリの自動更新は、OSの署名とは別に、更新機構が持つ独自の鍵で署名する。この鍵の厳重な管理を必須とする。自動更新の対象は macOS の `.app.tar.gz`、Linux の AppImage、Windows の NSIS 版とし、Linux の tar.gz・.deb は再導入で更新する。詳細はビルド・配布手順書（release/07-build-and-distribution.md）に従う。

## 4. データ保存・同期方針（提案）

MVPはローカルファーストとし、データはすべて利用者の端末に保存する。サーバーを持たないため、開発・運用コストが低く、業務メモを外部に送らない点を販売上の安心材料にできる。

保存形式は、内部では単一のローカルデータベース（SQLite等）を使い、利用者向けには日付ごとの Markdown 書き出しを提供する。保存先フォルダは設定で変更できる。利用者が iCloud Drive や Dropbox 配下を指定することもできるが、データベースをそこに置いてよいのは「同時に1台だけで開く場合」に限る。保存先がクラウド同期フォルダと判定できる場合は、その旨の警告を表示する。複数端末で使う場合は、Markdown 書き出しまたはバックアップの同期を推奨する。同時編集の競合解決はMVPでは保証しない。

公式のクラウド同期は、MVP 後の有料機能（ロードマップの「有料機能 B」）として検討する。その際はエンドツーエンド暗号化を前提とする。

## 5. 画面構成とモード

画面の中心は「整理モード」と「ノートモード」の2つで、同じ日付のボードの表と裏として切り替える。どちらも画面全体を使う。日付の一覧や設定への入り口として閉じられるサイドバーを置き、ノートモードでは閉じる。このほかに、過去の日を見返す「ふりかえり」画面を置く。

図：1日の流れ（2つのモードと持ち越し）

```
ノートモード ─行送り（Mod+Shift+T / Mod+Shift+B）▶ TODO・障害
整理モード ⇄ ノートモード（Mod+J）
整理モード ─終業時▶ 振り返り ─次の日の初回表示▶ 持ち越し ─確定▶ 次の日の整理モード
```

整理モード（既定）は、TODO、障害・詰まり、振り返りの3領域を1画面に並べる。配置は既定のレイアウト3種（3列の横並び、左にTODOで右に障害・振り返りの2段、縦積み）から選べる。初期値は左にTODO、右に2段とし、自由なドラッグ配置や比率変更は行わない。画面上部には日付を出し、その下に「凪メーター」を置く。凪メーターは空と海の景色で、太陽が時刻、波が残りの仕事、海面の光の道が終えた仕事を表し、残りが 0 件になると波が平らになる（凪）。残り件数・完了件数・持ち越し件数など最小限の情報も、凪メーターにまとめて出す。

ノートモードは、その日のメモ欄を全面に開く。プレーンテキストを基本とし、行頭の「- 」による箇条書き程度の簡易記法に対応する。TODOや障害へ送った行は、薄い印で区別して表示する。

ふりかえり画面は、週ごとの各日の様子と、過去の日の振り返り・ノートを見返す画面とする。週の振り返り（F-13）もこの画面に載せる想定とする。

## 6. 機能要件

MVPで必須（Must）とするのは、F-01〜F-08 と F-10、AIエージェント連携（A-01〜A-08）、Vimモードである。Vimモードの仕様は7章で定める。AIエージェント連携の範囲は本章の後半で定める。優先度は Must（MVP必須）、Should（MVP推奨）、Could（後続）の3段階とする。

| ID | 機能 | 要件 | 優先度 |
| --- | --- | --- | --- |
| F-01 | 日付ボード | 起動時は常に今日のボードを開く。前日・翌日・任意日付へ移動できる。日付の切り替わり時刻は設定可能（既定 4:00） | Must |
| F-02 | TODO | 1行1件で追加・編集・完了・削除・並べ替えができる。完了は取り消し線で残す。優先度や見積もり時間などの属性は持たず、並び順で優先度を表す | Must |
| F-03 | 障害・詰まり | 1行1件で追加・編集・解消・削除ができる。解消時に一言メモを残せる | Must |
| F-04 | 振り返り | 自由記述欄。任意で「良かったこと／詰まったこと／明日の一手」の見出しテンプレートを挿入できる | Must |
| F-05 | ノートモード | ショートカットでメモ欄を全面表示し、同じキーで整理モードへ戻る。カーソル位置を保持する。ノートは1日1枚とし、ショートカット（案：Mod+Shift+H）で「## 10:00 定例」のような時刻付き見出しを挿入して会議ごとに区切れる | Must |
| F-06 | 行送り | ノートの現在行または選択行を、ショートカットでTODOまたは障害へ送る。送った行には送信済みの印を付け、ノート側の原文は残す | Must |
| F-07 | 持ち越し | 新しい日の初回表示時に、前回の日（今日より前で、項目またはノートが存在する直近の日）の未完了TODOと未解消の障害・詰まりを一覧で提示し、まとめて、または選んで今日へ持ち越す。それより前の日は対象にしない。TODO・障害とも持ち越し回数を表示する。既定3回以上（設定で変更可）持ち越したTODOには「分割する／やめる」の選択肢を添えて見直しを促す（そのまま持ち越すことも可）。「外部ツールへ戻す」は、外部ツール連携（F-15）が有効で、かつ外部課題と紐付いたTODOにだけ表示する | Must |
| F-08 | 自動保存 | 入力停止後すぐに保存し、保存操作を不要にする。保存状態は控えめに表示する | Must |
| F-09 | 過去日の編集 | 過去のボードを今日と同じように編集できる（閲覧は F-01 で提供） | Should |
| F-10 | 全文検索 | 全日付のTODO・障害・振り返り・ノートを横断検索する | Must |
| F-11 | 書き出し | 1日または期間を Markdown で書き出す | Should |
| F-12 | 設定 | ショートカット割当、Vimモードの有効化、レイアウト（既定3種から選択）、テーマ（OS に合わせる／ライト／ダーク。既定は OS に合わせる）、フォントサイズ、ノートの書体（本文の書体／等幅）、保存先、日付の切り替わり時刻、言語（日本語／英語）、エージェントの権限、バックアップ、持ち越し見直しの回数（既定3）、更新の自動確認 | Should |
| F-13 | 週の振り返り | 直近7日の振り返りと完了数を1画面で見る | Could |
| F-14 | クラウド同期 | 複数端末間の公式同期（有料） | Could |
| F-15 | 外部ツール連携 | Linear・Jira の割り当て課題の取り込み、完了の書き戻し、障害との紐付け（有料） | Could |

障害・詰まりも TODO と同じく持ち越しの対象とし、始業時に「まだ詰まっているか」を確かめる機会にする。障害にも持ち越し回数を表示するが、見直しの選択肢は TODO にのみ添える。

### 将来構想：チーム用プロジェクト管理ツールとの連携

将来、Linear や Jira などと連携し、自分に割り当てられたタスクを Yunagi に取り込めるようにする（F-15、優先度 Could、有料オプション。ロードマップの「有料機能 A」）。ただし Yunagi はプロジェクト管理ツールにはならず、外部ツールを「元帳」、Yunagi を「今日の作業面」と位置づける。

割り当て済みタスクを毎日すべて TODO に流し込むと、「今日1枚」の整理が崩れる。そこで、割り当て一覧を受信箱として表示し、利用者が今日やるものだけを選んで TODO へ送る方式とする。ノートから行を送る操作と同じ体験にそろえる。

取り込んだ TODO には元の課題へのリンクと現在の状態を表示する。Yunagi で TODO を完了にしたときは、外部ツールの課題も完了状態へ書き戻す。どの状態を完了とみなすかはサービスごと（Jira はプロジェクトごと）に一度だけ設定し、進行中やレビュー中などそれ以外の状態は同期しない。認証情報は OS のキーチェーンに保存し、ローカル版ではサーバーを経由せず端末から直接 API を呼ぶ。

障害・詰まりにも外部の課題を紐付けられる。紐付けた課題のリンクと現在の状態を表示し、課題が完了したら障害の解消を促す。実際に詰まりが解けたかは本人にしか分からないため、自動では解消しない。

### AIコーディングエージェントとの連携（MVPから提供）

Claude Code や Codex などの AI コーディングエージェントとの連携を、MVPから提供する中核機能とする。想定利用者のエンジニアにとって、エージェントに仕事を渡し、その結果を今日の整理に戻す流れは日常になりつつある。「エージェントとつながる日次ノート」を公開時点からの差別化の中心に据える。

連携の手段は、MCP（Model Context Protocol）サーバーとコマンドラインツール（CLI）の2つとする。MCP は主要なエージェントが共通して対応する接続方式で、一度作れば複数のエージェントから使える。CLI は `yunagi todo add "…"` のような形で、エージェントだけでなくシェルスクリプトや git フックからも呼べる。

| 方向 | 想定する使い方 |
| --- | --- |
| Yunagi → エージェント | 今日の TODO やノートを読み、作業の文脈として使う。TODO の1行をエージェントへの依頼として渡す |
| エージェント → Yunagi | 作業中に見つけた問題を障害・詰まりに記録する。終えた作業を振り返りの下書きに追記する。TODO を完了にする |

エージェントが書いた項目には印を付け、人の記述と区別する。権限は既定で読み取りのみとし、書き込みは利用者が明示的に許可した場合に限る。CLI からの書き込みも同じく既定で読み取りのみとし、権限の変更はアプリの設定画面か、対話端末上の確認でしか確定できない。ただし CLI は人とエージェントを確実には区別できないため、防御の境界とはみなさない（詳細は MCP・CLI 仕様書）。MCP サーバーと CLI は端末内で動き、データを外部に送らない。アプリ起動中の同時書き込みに備え、読み書きはアプリ本体を経由させるか、データベース側で排他を保証する。

MVPで提供する範囲は次のとおりとする。MCP と CLI は同じ操作を同じ名前で持ち、どちらからでも同じことができるようにする。ただし A-07（導入）と A-08（権限と履歴）は利用者が行う管理操作のため、CLI とアプリにだけ置き、MCP には出さない。

| ID | 区分 | MVPで提供する操作 |
| --- | --- | --- |
| A-01 | 読み取り | 今日または指定日のボード全体（TODO・障害・振り返り・ノート）を取得する。未完了 TODO と未解消の障害だけを取得する |
| A-02 | 読み取り | 過去日を含めて全文検索する |
| A-03 | TODO 操作 | TODO の追加・編集・完了・完了の取り消し（未完了に戻す）を行う |
| A-04 | 障害操作 | 障害・詰まりの追加・編集と解消（解消メモ付き）を行う |
| A-05 | 追記 | 振り返りとノートの末尾に追記する。ノート編集の許可がある場合に限り、ノートの既存の行の書き換え・削除・並べ替えもできる。振り返りの既存の文章は書き換えできない |
| A-06 | 依頼の受け渡し | Yunagi で選んだ TODO を、関連するノートの行とあわせてエージェント向けの依頼文として書き出す（クリップボード、または CLI の標準出力） |
| A-07 | 導入 | `yunagi agent setup` の1コマンドで、Claude Code と Codex の設定に MCP サーバーを登録する |
| A-08 | 権限と履歴 | 読み取り・TODO 操作・障害操作・追記・ノート編集ごとに許可を切り替える。ノート編集は既定で無効とする。エージェントによる変更を履歴として一覧し、1件ずつ取り消せる |

エージェントを Yunagi から直接起動する機能、エージェントの作業終了を自動で振り返りに記録するフック連携、変更のリアルタイム表示は第2フェーズ（ロードマップ参照。エージェント関連の無料拡張）で検討する。なお MVP でも、エージェントによる変更は画面の再読み込みで最新の状態を表示する。第2フェーズの「リアルタイム表示」は、変わった項目の強調などの演出を指す。

## 7. 操作体系（キーボードショートカット）

すべての機能をマウスなしで操作できることを必須とする。以下は代表的な初期割当の案で、macOS は ⌘、Windows・Linux は Ctrl を Mod と表記する。全項目を設定で変更可能にする。全一覧と正本は操作仕様書（design/04-interaction-spec.md）とする。

| 操作 | 初期割当（案） | 範囲 |
| --- | --- | --- |
| Yunagi を前面に呼び出す | Mod+Alt+Y（macOS の ⌘⌥Y。Windows・Linux は Mod を使わず Alt+Shift+Y） | OS全体 |
| ノートモード ⇄ 整理モード | Mod+J | 共通 |
| 現在行をTODOへ送る | Mod+Shift+T | ノート |
| 現在行を障害へ送る | Mod+Shift+B | ノート |
| 領域の移動（TODO／障害／振り返り） | Mod+1 / 2 / 3 | 整理 |
| 項目の完了・解消の切替 | Mod+Enter | 整理 |
| 項目の上下移動 | Alt+↑ / ↓ | 整理 |
| 前日・翌日へ移動 | Mod+\[ / \] | 共通 |
| 今日へ戻る | Mod+T | 共通 |
| 検索 | Mod+K | 共通 |

日本語入力（IME）の変換確定中は、Enter や修飾キーの操作をショートカットとして扱わないことを必須とする。日本向け販売では、ここでの誤動作が最大の離脱要因になりうる。

### Vimモード

Vim のキー操作で使える「Vimモード」をMVPから備える（優先度 Must）。既定は無効とし、設定で有効にする。完全な Vim 互換は目指さず、日常的に使う操作に絞る。

ノートモードと振り返り欄では、ノーマル・挿入・ビジュアルの各モードと、基本的な移動（h j k l、w b、gg G など）と編集（dd、yy、p、u、. など）に対応する。行送り（F-06）もノーマルモードから行えるようにする（案：`<Space>t` で TODO へ、`<Space>b` で障害へ）。

整理モードでは、j / k で項目間を移動し、o で直下に新規追加、i で編集、x で完了・解消の切り替え、dd で削除を行う。Mod キーを使う既存のショートカットは、Vimモード中も同じように使える（Windows・Linux の Mod+[ / ] を除く。Ctrl+[ が Vim の Esc と重なるため、Vimモード有効時の前日・翌日への移動は Alt+[ / Alt+] とする。詳細は操作仕様書 4.1）。

日本語入力と両立させるため、挿入モードからノーマルモードに戻ったときは IME を自動で英数入力に切り替える。ノーマルモード中は、IME の状態にかかわらずキー入力を Vim の操作として扱う。

## 8. 非機能要件

軽さを数値で担保する。以下の目標値は、一般的な業務用ノートPCでの計測を前提とした案である。

| 区分 | 要件（目標値案） |
| --- | --- |
| 起動 | 常駐状態からの呼び出しは 200ms 以内、コールド起動は 1.5 秒以内 |
| 入力応答 | キー入力から表示まで 16ms 以内（体感遅延なし） |
| 自動保存 | 入力停止から 0.5 秒以内に保存。強制終了・電源断でも直前数秒以上は失わない |
| オフライン | すべての機能がネットワークなしで動作する |
| データ量 | 5年分（約1,800日）のデータで検索 1 秒以内 |
| プライバシー | Yunagi は利用者の記述内容を外部送信しない。利用統計を取る場合はオプトインとする |
| 対応OS | Windows 10/11、macOS 直近3世代（Apple Silicon）、Intel Mac は対応する最後の macOS まで（要確認）、主要な Linux ディストリビューション（Ubuntu LTS、Fedora など） |
| 言語 | 日本語・英語の UI を初期リリースから同時に提供する。画面の文言は最初から多言語化を前提に管理する |
| アクセシビリティ | ライト／ダークテーマ（既定は OS の外観設定に追従）、フォントサイズ変更、十分なコントラスト |
| 更新 | アプリ内からの自動更新に対応し、更新時にデータを壊さない。更新の確認は既定で有効とし、設定で無効にできる。確認時に送る情報は版・OS・アーキテクチャのみ（配布ホストには IP アドレスと日時が記録される） |

データ損失は致命的な不具合とみなし、定期的な自動バックアップ（直近7日分など）を保存先に作成する。

## 9. 配布・収益モデル

アプリ本体は無料で配布し、公式クラウド同期と外部ツール連携（Linear、Jira など）を月額の有料オプションにする。前者は運用コストが発生する機能、後者は業務で使う人ほど価値が高い機能である。個人の日次整理という中核体験は無料のまま提供する。

AIエージェント連携（MCP・CLI）は、第2フェーズ（ロードマップ参照）の機能も含めて無料とする。AIの利用料は利用者が各AIサービスと結ぶ契約の中で支払われ、Yunagi は接続口を提供するだけで、サーバー費用も発生しないためである。

同期を提供するまでの収入源として、公開時から任意の「サポーターライセンス」（買い切り）を販売する。機能差は付けず、買わなくても全機能を使える。1 回の購入で、以後の版も使える。価格は 2,500 円（税込。消費税の扱いは販売の仕組みを決めるときに確かめ、必要なら表示を直す）、特典は「有料同期の初年度が半額」と「このアプリについて」のサポーター表示（記念）とする。有料同期の月額は月 500 円（仮）を初期の目安とする。これらは売れる前の仮説で、公開から数か月後に見直す（根拠と見直しの時期はロードマップ 4章）。

有料同期は、利用者が Dropbox や Syncthing、git などで自力同期できる状況でも選ばれる必要がある。そのため、エンドツーエンド暗号化、同時編集時の競合解決、設定不要の導入を必須の差別化要素とし、モバイル・Web からの閲覧を将来の候補とする。同期では利用者の業務データを預かるため、障害対応、漏えい対策、プライバシーポリシーをローカル版より厳格に整備する。

配布経路は公式サイトのみとし、Mac App Store・Microsoft Store では販売しない（「公式サイトのみ」は「ストアでは販売しない」の意味である。配布物の実体は GitHub Releases に置き、利用者への案内は公式サイトに一本化する。Homebrew は v1.0 では出さない。ビルド・配布手順書 4.3）。ライセンスキー発行と決済には外部の販売プラットフォームを使う想定である。

この方式には3つのリスクがある。ターミナル操作に慣れない利用者には導入の壁になること、Apple や Microsoft が将来この扱いを厳しくする可能性があること、未署名アプリへの不安が購入をためらわせうることである。対策として、画面付きの導入手順ページ、配布物のハッシュ公開、ソースまたはビルド手順の透明性を用意する。

利用規約、プライバシーポリシー、特定商取引法に基づく表記、問い合わせ窓口を公開時までに用意する。

## 10. スコープ外

「今日1枚」というコンセプトを守るため、次の機能は作らない。要望があっても、他の専用ツールに任せる方針とする。

- プロジェクト、タグ、階層構造による長期タスク管理
- 期限日、繰り返しタスク、リマインダー通知
- チームでの共有、共同編集、担当者の割り当て
- 画像や添付ファイルの貼り付け（MVP時点）
- モバイルアプリ（MVP時点）
- カレンダーや外部タスクツールとの連携（MVP時点）
