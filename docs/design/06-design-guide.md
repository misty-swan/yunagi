# デザインガイド

## 1. コンセプト

名前の由来である「夕凪（ゆうなぎ）」は、夕方に海風が止み、海面が静まる時間帯を指す。Yunagi の画面は、散らかった1日を書き出して静かに見渡せる状態をつくることを目指す。本文の情報は、装飾ではなく、余白と文字の階層で整理する。

画面上部の「凪メーター」には、空と海の景色を置く。太陽でいまの時刻、波で残りの仕事、海面の光の道で終えた仕事を表し、仕事が片付くほど海が静まって、残りが 0 件になると凪になる。景色は飾りではなく、その日の状態を一目で伝えるための表現とする（画面設計書 3章「凪メーター」）。

## 2. 原則

1. 本文は紙の1枚に見えること：本文の領域の境界は余白と細い罫線で示し、影は重ねて表示するパネルとポップオーバーだけに付ける。サイドバーは閉じられるものとし、ノートモードでは閉じる（画面設計書 3章「画面の骨組み」）。
2. 動かないこと：アニメーションは状態の変化を伝える場合に限り、100ms 以内とする。凪メーターにも動きは付けず、色と形がその場で切り替わるだけとする。
3. 色は意味と、凪メーターの景色のために使う。景色の色は文字に使わない：強調色は夕陽の `--accent`（文字には `--accent-strong`）とする。「夕陽色の文字」はすべて `--accent-strong` を指し、`--accent` は面と装飾だけに使う。ほかに使ってよいのは状態・出所・情報を示す `--warn`・`--done`・`--agent`・`--sea` と、景色のトークンだけとし、3章にない色を足さない。
4. 文字が主役：アイコンは補助とし、ラベルのない操作アイコンは置かない。

### ノートの等幅

ノートの等幅は、和文も含めて同梱のフォントで表示し、どの OS でも同じ見た目で、半角2文字と全角1文字の幅をそろえる（2026-11-03 決定）。OS 標準の和文等幅は、次のとおり必ず入っているとは限らず、字形も OS ごとに違うため使わない。同梱するので、OS に和文等幅が無いときの代替は要らない。

- macOS：Osaka−等幅（Osaka-Mono）は、Apple の一覧（Fonts included with macOS Tahoe）で「入っているか、ダウンロードできる」フォントに載る。入っていないときは Font Book から取り込む必要がある（オンデマンド）。
- Windows：MS ゴシックと BIZ UDゴシックは「日本語の追加フォント（Japanese Supplemental Fonts）」に入る。日本語版や日本語を足した環境には入るが、英語版などを新しく入れた環境には入っていない（Microsoft Learn「How to add fonts missing after upgrading Windows」、BIZ UDGothic font family）。
- Linux：Noto Sans Mono CJK JP が、Debian・Ubuntu では `fonts-noto-cjk`、Fedora では `google-noto-sans-mono-cjk-vf-fonts`、Arch Linux では `noto-fonts-cjk` にある。Ubuntu のデスクトップは `fonts-noto-cjk` を標準で入れる（`ubuntu-desktop-minimal` の推奨）が、ほかは入れるときの言語や利用者の導入しだい。

選ばなかったもの：

- JetBrains Mono と BIZ UDゴシックの2つを同梱し、`font-family` で並べて和文だけ BIZ UDゴシックで表示する組み合わせ：JetBrains Mono の半角は 0.6em で、半角2文字（1.2em）と全角1文字（1.0em）がそろわない。
- 等幅でも太字・斜体を出す（配布元の `UDEVGothicHS-Bold.ttf` など、本物の太字を足す）：太字1つで 3.87 MB 増える。ノートは本文と同じ書体のときも強調を飾らず書いたとおりに出す（上の表の「太さ」）ので、Regular だけにする。ノートで太字を出すと決めたら、`UDEVGothicHS-Bold.ttf` を足し、この表の「太さ」を直す。
- BIZ UDゴシック単体：桁はそろうが、英数字が JetBrains Mono でなくなり、ファイルも大きい（Regular で 4.67 MB）。
- UDEV Gothic のほかの版：35 版は半角3：全角5で桁がそろわない。JPDOC 版は矢印・罫線などを全角にし、英語の文やコードの桁がずれる。LG 版は合字（`->` などを1つの記号に見せる）で、書いた文字のとおりに見えなくなる。通常版は全角スペースを点線の箱で見せるプログラミング向けの表示で、日本語の文章が中心のノートでは字下げなどの全角スペースが目障りになる。

予約フォント名：UDEV Gothic のライセンスは「UDEV Gothic」を予約フォント名にしている。手を加えた版はこの名前で配れず、形式の変換もふつうは手を加えたことになる（OFL FAQ 2.2）。このため公式のファイルを加工せずに入れる。変換や文字の削減が要るようになったら、OFL に従って別の名前を付ける。

## 5. 余白とレイアウト

- 画面の左右余白は 28px。サイドバーの幅は 240px、上部のバーの高さは 60px、凪メーターの高さは整理モードで 112px、ノートモードで 58px。
- 1行の項目の高さは本文 15px のとき 36px。
- 整理モードの列の間は 56px。ノートの本文の幅は 680px。
- 角丸：パネル 14px、カード 12px、ボタン・行 8〜10px、チェック欄（障害）4px。
- 影：重ねて表示するパネルとポップオーバーだけに薄い影を付ける。ほかは罫線と面の色で区切る。値はパネル（S-03・S-04）`0 18px 48px rgba(0,0,0,.18)`、ポップオーバー（保存の失敗の原因など）`0 8px 24px rgba(0,0,0,.12)`（ライト・ダーク共通。2026-11-03 決定）。
- 狭い画面での縦積みとサイドバーを閉じる切り替えは、画面設計書（03-ui-spec.md）3章「レイアウト」に従う。
- 寸法と文字の大きさは、本文 15px のときの値。文字サイズの設定（4章）を変えると、すべて同じ比で拡縮する。

## 7. 文言

- 短く、命令形を避け、状態を淡々と伝える（例：「3回持ち越しています。分割しますか？」）。
- 感嘆符、絵文字、励ましの言葉は使わない。
- 日本語と英語の文言は同じ情報量に揃え、文言キーで管理する。
- ラベル（領域見出し、ナビ、凪メーター、キーの案内、件数、日付の表示、パレットのグループ名と種類）は、日本語 UI でも英語で書く。
- 文（状態の説明、確認、操作ボタン、空の状態、エラー、コマンド名）は各言語で書く。例：「今日やることを書く（Enter）」「保存できていません」「選んだものを持ち越す」。
- TODO が空の日の文言：今日は「今日やることを書く（Enter）」、今日以外は「やることを書く（Enter）」。英語は Write what to do today (Enter) ／ Write what to do (Enter)（画面設計書 3章「空の状態」）。

## 9. 試作品（prototype/）との関係

- 試作品（リポジトリ直下の `prototype/`、Claude Design で作成）は、デザイン案D「夕凪」（2026-11-02 採用）で作っており、本書の値を使う。色は 3章のトークン（ライト・ダークとも）を CSS 変数（`prototype/tokens.css`）としてそのまま使い、独自の色を足さない。
- 試作品で見た目を調整した場合は、確定した値（色、文字の大きさ・太さ、行間、余白、罫線）を本書に書き戻し、本書を正本とする。本番のアプリは本書の値で実装する。
- 色を変えた場合は、3章のコントラスト基準（`--bg`・`--side`・`--surface` のすべてに対し、本文 7:1、補助情報・状態色 4.5:1 以上。チェック欄の枠は 3:1 以上）を再計算してから書き戻す。
- 画面の構成要素や操作が試作品と食い違う場合は、画面設計書（03）と操作仕様書（04）に従う（画面設計書 12章）。

## 10. 公式サイト

公式サイト（`site/`。作り方は ビルド・配布手順書 2章）は、アプリの画面とは別の媒体なので、本書は出発点（夕凪の世界観・ロゴ・基調の色）とし、上限にはしない。ただし、色と書体は、サイト専用の値を決めるまで 3章・4章のとおり（独自の色を足さない。書体は同梱の Inter。外部のサーバーに接続しない）。サイトの方向（配色の拡張・書体・構成・控えめな動き）を変えるときは、決めた値をこの章に書き、試験（`site/site.test.ts`）を合わせて直す。
