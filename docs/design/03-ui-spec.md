# 画面設計書（UI仕様）

## 1. 原則

- 本文が「その日の紙1枚」として見えることを最優先する。サイドバーは閉じられるものとし、ノートモードでは閉じる。
- 表示する情報は、日付、凪メーター、3領域（または全面のノート）、控えめな状態表示だけに絞る。
- すべての画面はキーボードだけで操作できる。マウス操作は補助として受け付ける。

## 3. S-01 整理モード

### 画面の骨組み

画面は「サイドバー」「上部のバー」「凪メーター」「本文（整理／ノート／ふりかえり）」「キーの案内」の5つで構成する。S-02・S-08 も同じ骨組みを使う（凪メーターの扱いは各章）。

件数（凪メーター・Recent・Today と Agents の件数）が読めなかったときも本文は出し、凪メーターと Recent・件数は、次に読めるまで出さない（前に表示していた日の件数を残さない。2026-11-03 決定）。

#### サイドバー

幅 240px。上から次の順に置く。

| 上から | 内容 |
| --- | --- |
| ロゴ | アイコン（24px）＋小文字の「yunagi」 |
| ナビ | Today（今日の残り件数）／ Archive（ふりかえり S-08）／ Agents（未確認の変更の件数。選ぶと変更履歴 S-06）。Inbox（外部課題の受信箱 S-07）は、外部ツール連携（有料機能 A）を有効にした利用者にだけ Agents の上に表示する。MVP では出さない（押せない項目を毎日見せない） |
| Recent | 今日と、項目やノートのある直近の日（今日を含めて最大7日）。各行に、その日の海の様子を小さな波で、完了数／TODO数を右に。すべて終えた日は波が平らな夕陽色の線になる |
| 下端 | Settings（Mod+,）、状態（エージェントの接続、「Saved locally」または保存失敗、新しい版があるときは「New version」。選ぶと更新内容と「更新して再起動」を表示。サイドバーを閉じているときは「New version」を上部のバーの右側に出す） |

- Recent の日の決め方（2026-11-03 決定。コアの `domain::board`）：今日は、項目もノートも無くてもいつも先頭に置く。続けて、今日より前で項目かノートのある日を新しい順に並べる。「項目やノートのある」は、持ち越しの「前回の日」と同じ決まり（削除されていない項目があるか、ノートが空白以外の文字を含む。データモデル設計書 3章 item）とし、振り返りだけの日は入れない。今日より後の日（先の日付に足した項目など）は入れない。件数はデータモデル設計書 3章「件数の数え方」で数える。
- Mod+\\ で開閉する。ノートモードに入ると自動で閉じ、整理モードに戻ると元に戻す。広いウィンドウの整理モードでの開閉だけを設定 `sidebar` に保存し、起動のとき当てる（ノートモードの間と幅 900px 未満での一時的な開閉は保存しない。2026-11-04 決定）。
- ウィンドウ幅 900px 未満では閉じる（Mod+\\ で明示的に開いたときだけ表示）。
- 閉じているときは、上部のバーの左端にロゴを出す。
- 開閉の決まりの細部（2026-11-03 決定）：ノートモードの間も Mod+\\ で開閉でき、整理モードに戻るとその開閉は捨てて、整理モードでの状態に戻す。幅 900px 未満で Mod+\\ で開いた状態は、幅が 900px 以上に戻ると捨てる（次に狭くなったときはまた閉じる）。幅 900px 未満での開閉は、広いときの開閉の状態を変えない。
- Recent は、表示している日が入っていなくても足さない（今日と、項目やノートのある直近の日だけ。表示している日が入っていれば、その行を選択中にする）。Recent の行を選ぶとその日を表示し、ナビの Today を選ぶと今日の整理モードを表示する（2026-11-03 決定）。

#### 上部のバー

高さ 60px。左から「（サイドバーが閉じているときだけロゴ）」「‹ 日付 ›」「Today」「Board / Note の切り替え」、右端に「検索欄（押すとパレット S-04、Mod+K）」「エージェントによる未確認の変更（◆ 件数）」「New version（サイドバーを閉じていて、新しい版があるときだけ）」「保存状態（保存中のみ小さな点。保存済みは非表示）」。

- 日付は `10.29 Thu`（数字は等幅）。年は出さない（パレットの日付ジャンプでは `2026.10.28 Wed`）。
- 「Today」は、今日を見ているときは夕陽色の枠の印（文字と枠とも `--accent-strong`）、ほかの日を見ているときは押せるボタン（「Today ⌘T」）になり、今日へ戻る（Mod+T）。
- ‹ › と Mod+[ / Mod+] で前日・翌日へ移る。モード（整理／ノート）は変えない。
- 表示している間に今日の論理日付が変わったとき（日付の切り替わり時刻を越えたとき）は、今日を表示していたなら新しい今日へ移り、ほかの日を表示していたならその日のまま、Today の印・Recent・凪メーターの時刻だけを変える（2026-11-03 決定。持ち越し S-03 の表示は 10章）。
- New version：サイドバーを閉じているときは、上部のバーの右側（保存状態の左）に出す。選ぶと更新内容と「更新して再起動」を表示する。
- New version の細部（2026-11-05 決定。YUN-83。`src/shell/UpdateNotice.svelte`、状態は `src/lib/update.svelte.ts`。動きはビルド・配布手順書 5.1）：
  - 出すのは、コアが新しい版を見つけているとき（ダウンロード中・失敗・再起動中も含む）だけ。更新の自動確認が無効のとき、設定が空のとき、自動更新の対象でない配布のときは、何も出さない。
  - 見た目：サイドバーの下端は、「Saved locally」の下に、`--accent-strong` の 11.5px の「New version」と小さな夕陽色の点を 1 行で出す。上部のバーは、サイドバーを閉じているときだけ、保存状態の左に 12px で出す。どちらも選ぶと小さな表示（幅 300px。サイドバーでは上へ、上部のバーでは下へ開く）を開く。外を押す・Esc・フォーカスが外へ出るで閉じる。
  - 表示の中身：「新しい版 1.2.0」（English: Version 1.2.0 is available）、更新内容（プレーンテキスト。HTML として解釈しない。長ければ高さ約 160px で縦に送れる。無いときは「更新内容は届いていません。」）、「入力中の内容は保存してから再起動します。」、[閉じる] と [更新して再起動]。
  - 「更新して再起動」を選ぶと（パレットのコマンドからも同じ）、入力中の内容を保存し終えてから始める。保存に失敗している間は始めず、「保存できていないので、更新を始めません。保存できてからやり直してください。」を出す。始まると表示の中に「ダウンロードしています 42%」（割合が分からないときは割合なし）を出し、その間は [更新して再起動] を押せなくする。署名の検証までに失敗したら「更新できませんでした。何も入れ替えていません。もう一度試せます。」を出し、[更新して再起動] を選び直せる。入れ替えが終わると「再起動します」を出し、アプリが再起動する。
  - 作業中に自動で再起動しない。状態が変わる（見つかる・無効にして消す・取り下げで消える）ときは、通知だけが出入りし、開いている表示は、通知が消えたときだけ閉じる。
- 未確認の変更：change_log に `seen_at` が NULL の記録があること（データモデル設計書）。S-06 で確認すると印は消える。
- 短時間の知らせ（2026-11-03 決定。`src/lib/notice.svelte.ts`）：持ち越し済みの項目や取りやめた TODO を変えようとしたとき（操作仕様書 2章）などは、上部のバーの右側（検索欄の左）に、文を `--text-muted` の 12px で 4 秒だけ出す（読み上げにも伝える）。次の知らせが来たら置き換える。整理モードで出す文は次のとおり（日付は `11.03 Tue` の形）。
  - 持ち越し済みの項目を変えようとした：「11.03 Tue へ持ち越し済みです」（Carried over to 11.03 Tue）
  - 取りやめた TODO を変えようとした：操作仕様書 2章の文
  - 持ち越し先の削除を Mod+Z で戻せない（データモデル設計書 3章 item）：持ち越し元が変わったときは「持ち越し元の項目が変わったため、戻せません」（Can't restore: the item it was carried over from has changed）、ほかの項目へ持ち越し済みになったときは「持ち越し元の項目が 11.05 Thu へ持ち越し済みのため、戻せません」（Can't restore: the item it was carried over from is carried over to 11.05 Thu）
  - 送り直しても成功しない失敗で、自動保存が送った内容を捨てたとき（アーキテクチャ設計書 4.1「自動保存」）：持ち越し済み・取りやめた TODO が理由なら上の文、ほかは「変更を保存できなかったため、表示を読み込み直しました」（Couldn't save the change, so the board was reloaded）。続けてボードを読み込み直す
  - 依頼文の書き出し（Mod+Shift+A。操作仕様書 2章。2026-11-05 決定。YUN-70）：コピーできたら「依頼文をコピーしました」（Request copied）、障害の行で押したら「依頼文にできるのは TODO です」（Only a TODO can be copied as a request）、書き出せなかったら「依頼文をコピーできませんでした」（Couldn't copy the request）
  - 定期バックアップを作れなかった（`backup-failed`。アーキテクチャ設計書 6.2）：「今日のバックアップを作れませんでした。自動で作り直します」（Today's backup couldn't be made. It will be retried automatically）。1日に1回しか届かず、ほかの知らせより長いので、10 秒出す。原因の文（ログ用）は出さない（コアが標準エラーに書く）。コアは 30 秒ごとに作り直し、作れても知らせない（2026-11-03 決定。入力は止まらず、保存の失敗ほど急がないので、保存失敗のような常時の表示にはしない）
- 保存に失敗した場合は、上部のバーの右端に `--warn` 色で「保存できていません」を常時表示し、成功するまで消さない（サイドバー下端の状態も保存失敗に変わる）。入力は継続でき、内容はメモリ上に保持して自動で再試行する。表示を選ぶ（またはパレットから開く）と、原因（保存先が見つからない等）と、再試行・保存先変更の操作を示す。原因の文は失敗の種類に合わせて書いたものにし、内部のエラーの文（開発者向け）をそのまま出さない（2026-11-03 決定。README「エラーの表示（Rust）」）。
  - 失敗している間は、保存中の点は出さず「保存できていません」だけを出す。
  - 原因の文（2026-11-03 決定。コアのエラーの種類で決める。`src/lib/i18n.ts`）：保存先の問題（`storage`）は「保存先に書き込めません。」（Can't write to the save folder.）、データベースを開いていない（`not_ready`）は「データベースを開けていません。」（The database isn't open.）、処理が途中で止まった（`internal`）は「保存の処理が途中で止まりました。」（Saving stopped partway.）。続けて「入力した内容はこの画面に保持し、自動で再試行しています。」と「再試行」のボタンを出す。保存先が見つからないことはいまのエラーの種類では見分けられないので、見分けられるようにするまでは「保存先に書き込めません。」で伝える。「再試行」の隣に「保存先を変える」を置き、選ぶと設定（S-05）のデータ区分を開く（2026-11-04 決定。保存先が外れたときに、そのまま保存先を変えられるように。7章）。
  - 原因の表示は、上部のバーの「保存できていません」の下に重ねるポップオーバーとし、Esc で閉じる。保存に成功したら閉じる。

#### キーの案内

画面下端に1行で、その画面の主なキーを `⌘K Search` のように出す。整理・ノート・ふりかえりで内容を変える。

- 整理：`⌘K Search`・`⌘J Note`・`⌘↵ Done`・`⌘[ ⌘] Day`・`⇧⌘L Archive`・`⌘\ Sidebar`
- ノート：`⇧⌘T To TODO`・`⇧⌘B To Blockers`・`⇧⌘H Time heading`・`⌘J Board`・`⌘\ Sidebar`
- ふりかえり：`← → Day`・`⌘[ ⌘] Week`・`↵ Open`・`Esc Back`
- Windows・Linux では ⌘ を `Ctrl+`、⇧ を `Shift+` にして出す（例：`Ctrl+Shift+L`）。幅が足りないときは折り返す。（2026-11-03 決定）

### 凪メーター

上部のバーの下に、空と海の景色を置く。整理モードでは高さ 112px、ノートモードでは 58px の小さい版とし、ふりかえり画面（S-08）では出さない。

| 要素 | 意味 | 表し方 |
| --- | --- | --- |
| 太陽 | いまの時刻 | 始業（既定 9:00）から終業（既定 19:00）まで、左から右へ弧を描いて進む。終業を過ぎると水平線に半分沈む。過去の日は終業の位置、未来の日は始業の位置 |
| 波 | 残りの仕事 | 未完了の TODO と未解消の障害の数（全体に対する割合）が多いほど高い。0 件になると平らな線になる（＝凪） |
| 光の道 | 終えた仕事 | 完了・解消した割合が大きいほど、太陽の下の海面に映る光の線が長く（本数が多く）なる |
| 空 | 雰囲気 | `--sky-1` から `--sky-2` へのグラデーション。太陽の位置に合わせて背景にうっすら光が差す |

- 左上に文字で、時刻（今日）／「Day end」（過去の日）／「Not yet」（未来の日）、大きく残り件数と「LEFT」、続けて「TODO 6 · Blockers 3 · Done 3/9 · ↻ Carried 4」を出す。残りが 0 件の日は「NAGI」と完了数だけを出す。
  - 細部（2026-11-03 決定）：「↻ Carried」は持ち越し件数が 1 以上のときだけ出す。項目が1件も無い日は凪にせず、「0 LEFT」だけを出し（内訳は出さない）、波は平らな線、光の道は無しとする。時刻は 30 秒ごとに読み直す。日付の切り替わり時刻（既定 4:00）より前の深夜は前の日の続きとして扱い、太陽は終業を過ぎた位置（沈んだ形）にする。
  - 光の道の本数は、完了・解消したものが1件でもあれば 2 本から、すべて終えると 8 本（終えた割合に比例）とする。
- 件数（完了数／TODO数、持ち越し件数、未解消の障害数）は凪メーターに表示する。
- 動きは付けない。操作や時刻に応じて、色と形がその場で切り替わるだけとする（デザインガイド 2章「動かないこと」）。
- 読み上げ用に「残り 9 件（TODO 6・障害 3）、完了 3/9、持ち越し 4」のようにまとめた説明を付ける。
- 時間帯（始業・終業）は設定（7章「一般」の「凪メーターの時間帯」）で変えられる。

### 各領域の表示

- 領域見出し：英字ラベル（TODO / BLOCKERS / REFLECTION）。見出しの右に、TODO は夕陽色の文字（`--accent-strong`）で残り件数（例：「6 left」）、障害は `--warn` で未解消の件数（例：「3 open」）を出す。
- チェック欄：TODO・障害の各行の先頭に置く（TODO は丸、障害は角丸の四角）。完了・解消すると塗りつぶし、白抜きのチェックを出す。クリックでも切り替えられる。
- TODO：1行1件。完了は取り消し線で残す。持ち越し回数が1以上の項目は行末に、線で描いた ↻ と回数を表示する。回数が持ち越し見直しの回数（設定「操作」、既定3）以上になると `--warn` にする（見直しの選択肢が出る回数と色の変わる回数をそろえる）。外部課題と紐付いた項目は課題キーと状態を表示する（将来・有料）。
- 障害・詰まり：1行1件。解消済みは取り消し線で残し、解消メモを本文の下の行に「→ メモ」の形で表示する。未解消に戻した障害に残っている解消メモは、未解消の間は表示しない（操作仕様書 2章）。持ち越し回数が1以上の障害も、TODO と同じく行末に ↻ と回数を表示する（見直しの選択肢は TODO のみ）。外部課題が完了した場合は「解消しますか」の控えめな表示を出す（将来・有料）。
- 振り返り：自由記述のエディタ。テンプレート挿入で「良かったこと／詰まったこと／明日の一手」の見出しを入れられる。見出しは夕陽色（`--accent-strong`）の小さな文字で表示し、「## 」はごく薄く表示する。
  - テンプレート（2026-11-03 決定。Mod+Shift+R、操作仕様書 2章）は、画面の言語で `## 良かったこと`・`- `・空行・`## 詰まったこと`・`- `・空行・`## 明日の一手`・`- ` の8行（英語は `## Went well`・`## Got stuck`・`## Next step for tomorrow`）。カーソルのある行が空ならその行から、そうでなければ次の行から入れ、最初の `- ` の後ろへカーソルを移す。空白（コアと同じ空白の文字）だけの行も空とみなして置き換え、CR を含む行は空とみなさない（ノートの時刻付き見出しの挿入と同じ。操作仕様書 2章）。「## 」で始まる行はどれも見出しとして表示する。
  - エディタは CodeMirror 6（アーキテクチャ設計書 3章）。その日の本文を読み終えるまでは入力を受け付けない（読む前の入力を失わないため）。

## 5. S-03 持ち越し

- その日に初めて Yunagi を表示したとき、「前回の日」（今日より前で、項目またはノートが存在する直近の日）に未完了 TODO と未解消の障害があれば、整理モードの上に重ねて表示する。それより前の日に残った項目は対象にしない。
- 見た目：パネルは `--surface`、角丸 14px、薄い影。背後は `--scrim` で覆ってぼかす。見出しは英字ラベル「CARRY OVER」と、文「前回の日（10.28 Wed）に残った項目」。各項目のチェックは丸。
- 一覧には、前回の日の未完了 TODO と未解消の障害のうち、まだ持ち越し済みでないもの（データモデル設計書 3章）を出す。開いたときは全項目にチェックが付いている。各項目のチェックを外して「選んだものを持ち越す」、または「すべて持ち越す」「持ち越さない」を選ぶ。キー操作：j/k または ↑/↓ で移動、Space で選択切替、Enter で「選んだものを持ち越す」、Esc で後回し。
- 後回しにした場合は、同じ論理日付のうちは、次にアプリを前面に出したとき1回だけ再表示する。それ以降も、パレット（6章）の「持ち越しを開く」コマンドで開ける（その日の持ち越しを終えるまで出る）。
- 持ち越した項目は、今日のリストの先頭に、前回の日の順のまま入る。
- 持ち越し回数が見直しの回数（設定「操作」、既定3回）以上の TODO には「分割する／やめる」の選択肢を添える。外部連携が有効で、かつ外部課題と紐付いた TODO にだけ「外部ツールへ戻す」も添える（将来・有料）。選ばずにそのまま持ち越すこともできる。「分割する」「やめる」の選択は、下の3つのボタン（「選んだものを持ち越す」「すべて持ち越す」「持ち越さない」）のどれを押しても反映する。
- 「分割する」を選ぶと、その場で子の TODO を複数行入力できる。子は今日に作られ（持ち越し回数 0）、`split_from_id` で元の項目を指す。元の項目（前回の日）は「やめた」扱いになる（`status=dropped`、`close_reason=split`。データモデル設計書）。子を1件も書かずに確定した場合は分割しない。
- 「やめる」を選んだ TODO は持ち越さず、前回の日の項目を `dropped`（`close_reason=dropped`）にする。「外部ツールへ戻す」は同じく `dropped`（`close_reason=returned_external`）にし、外部の課題はそのままにする。
- 持ち越した項目、持ち越さなかった項目のどちらも、前回の日の元の項目の状態（`open` 等）は変えない（「やめる」「分割する」「外部ツールへ戻す」を除く）。持ち越した後の元の項目は変えられない（データモデル設計書 3章）。
- この画面を表示している間に、エージェントが前回の日の項目を変えた場合は、一覧をその場で更新する。完了・解消した項目は外し、そこで選んでいた「分割する」「やめる」と、入力していた子の TODO は捨てる（その項目は完了・解消のまま）。未完了・未解消に戻した項目と、前回の日に追加した項目（`add_todo`・`add_blocker` の `--date`）は、チェックを付けずに加える。本文の変更は表示に反映する。確定の時点の一覧で持ち越す（「すべて持ち越す」は加えた項目も含めて一覧のすべて、「選んだものを持ち越す」はチェックの付いたものだけ。データモデル設計書 3章）。表示している間に、より新しい日に項目かノートができて「前回の日」が変わった場合は、確定を受け付けずに一覧を読み直す（2026-11-03 決定。データモデル設計書 3章 item）。

- 画面の細部（2026-11-03 決定。コードは `src/carryover/`、状態と操作は `src/lib/carryover.svelte.ts`、コマンドは `carryover_status`・`carryover_candidates`・`postpone_carryover`・`mark_carryover_reshown`・`confirm_carryover`）：
  - いつ確かめるか：データベースを開いたとき（起動も「アプリを前面に出した」ことに数える）と、アプリを前面に出したとき（窓のフォーカス）。持ち越しが残っていて、まだ後回しにしていなければ出す。後回しにした後は、前面に出したときに再表示を記録できたときだけ1回出す（再起動の後の起動でも1回）。常駐中に日付が変わったときは、そのまま前面にあっても入力を遮らないよう、次に前面に出したときに出す。
  - 出すときは、ふりかえり（9章）を開いていれば閉じ、今日の整理モードに切り替えて重ね、まだ保存していない入力を送り終えてから一覧を読む（送る前の本文・状態を写さないため）。読み終えるまでは見出しを「読み込んでいます」にし、確定の3つのボタンを押せなくする（後回しはできる）。読めなければ「一覧を読めませんでした。読み直しています。」を出し、1 秒ごとに読み直す。出している間は背後（外枠と本文）を操作できなくし、ほかの画面のキー（Mod+K・Mod+Z など）も受け付けない。背後にフォーカスが落ちたとき（覆いをクリックしたときなど）も、Esc は後回し、Enter は「選んだものを持ち越す」として効かせ、ほかのキーは行へフォーカスを戻すだけにする。Tab はこの画面の中だけを回る。開くと先頭の行へフォーカスを置き、閉じると開く直前の所へ戻す。読み直しで選んでいた行が消えたら、同じ位置の行へ移る。
  - 一覧は TODO・障害の順に、英字の見出し（TODO / BLOCKERS）の下に並べる。行末に持ち越し回数（↻n。見直しの回数以上は `--warn`。障害も同じ）。見直しの選択肢の行には「3回持ち越しています。分割しますか？」と「分割する」「やめる」を添える。選ぶと、その行のチェックを外して本文に取り消し線を引き、本文の後ろに選んだものを出す。同じものをもう一度押すと外してチェックを戻し、チェックを付けても外す。「分割する」を選ぶと、その下に子の TODO の入力欄（1行に1件）を開いてフォーカスを移す。欄の中の Enter は改行、Esc はその行のチェック欄へ戻る。
  - 「選んだものを持ち越す」では、子を1件も書かなかった「分割する」の項目も持ち越す（チェックは外れているが、分けるつもりの項目を前の日に置き去りにしないため。子のある分割はコアが先に扱う）。
  - 一覧の読み直しで、消えた項目のチェックと見直しの選択・子の入力は捨て、もう一度加わっても（未完了に戻した）チェックは付けない。見直しの選択肢が出なくなった項目（回数の設定が変わった）は、選んでいた見直しを捨ててチェックを戻す。前回の日が変わったとき（確定が `previous_day_changed` で断られたときを含む）は、開き直したものとして全項目にチェックを付け、「前回の日が変わったため、一覧を読み直しました。」を見出しの下に出す。一覧が空になったら「持ち越す項目はありません。」を出し、ボタンはそのまま使える。前回の日そのものが無くなった（前の日の項目もノートも消された）ときは、見出しを「前回の日に残った項目」にし、確定のボタンは何も書かずに閉じる。
  - 確定に失敗したとき（保存先の問題など）は、閉じずに「持ち越せませんでした。もう一度選べます。」を出す（内容を持ったまま自動で送り直さない。アーキテクチャ設計書 4.3「保存の失敗中」には数えない）。見直しの選択をコアが受け付けなかった（`invalid_argument`）ときは「見直しの選択を受け付けられませんでした。選び直せます。」を出す（分割の子は LF・CRLF・CR のどれでも行に分けて送るので、ふだんは起きない）。ほかの窓などで今日の持ち越しを終えていた（`carryover_done`）ときは閉じる。出している間にデータが変わったときも、持ち越しの状態を読み直し、ほかの窓・CLI などで今日の持ち越しを終えていたら閉じる。後回しと再表示の記録も、ほかの窓が状態を読み直すよう、データの変更として知らせる。修飾キー付きの Enter（Mod+Enter など）では確定しない（確定は Mod+Z で取り消せず、Mod+Enter の押し間違いを防ぐため。操作仕様書 2章「取り消し・やり直し」）。開く前にノートモードだったときは、閉じた後に、整理モードで前にフォーカスのあった所へ戻す。確かめて開く処理（起動・前面に出したとき・パレットから）は1つずつ行い、1回だけの再表示を記録したのに出さないことが無いようにする。後回しの記録に失敗しても閉じる（次に前面に出したとき、もう一度出る）。
  - 「持ち越しを開く」（6章）は、今日の持ち越しが残っている間だけ出す（`Carryover.pending`）。パレットから開いたものを Esc で閉じても、後回しの最初の時刻は変わらず、自動の再表示は増えない（データモデル設計書 3章 day）。

## 6. S-04 検索パレット

- 画面中央に入力欄と結果一覧を重ねて表示する。パネルの形は S-03 と同じとする。
- 入力欄が空のときは、コマンドの一覧を出す。
- 入力すると、結果を「日付へ移動」「コマンド」「検索結果」の順に見出し付きで並べる。グループ見出しは英字ラベル（GO TO DATE / COMMANDS / RESULTS）とする。
- 検索結果は日付・種類（英字ラベルで TODO / BLOCKER / REFLECTION / NOTE）・本文の一部で表示し、一致した部分は太字の夕陽色（`--accent-strong`）にする。Enter でその日のボードの該当位置へ移動する。
- 日付（`2026-10-31` や `yesterday`、`昨日`）を入力すると日付ジャンプとして扱う。「昨日」などの相対的な日付は、今日（論理日付）を基準にする。
- コマンド（設定を開く、レイアウト変更、変更履歴を開く、ふりかえり（Archive）を開く、サイドバーを開く・閉じる、持ち越しを開く（5章）、更新して再起動 等）もここから呼べる。いまの設定に当たるコマンドには「使用中」、キーのあるコマンドにはキーを右端に出す。

- 画面の細部（2026-11-03 決定。コードは `src/palette/`、状態と検索は `src/lib/palette.svelte.ts`、日付の読み方は `src/lib/date_query.ts`、一致した所の切り出しは `src/lib/search_match.ts`、コマンドは `search`）：
  - 開き方と閉じ方：Mod+K と上部のバーの検索欄で開く（外枠のほかの画面と同じ入口）。開くたびに入力は空から始める。Esc、もう一度 Mod+K、覆いのクリックで閉じ、開く直前にフォーカスのあった所へ戻る。持ち越し（5章）を出している間は開かない。開いている間に持ち越しが出たら、パレットを閉じ、持ち越しを閉じた後はパレットを開く前の所へ戻る。
  - キー：フォーカスは入力欄に置いたままにし（行はマウスでも選べる）、↑/↓ で行を移り（端では反対の端へ回る）、Enter で選ぶ。入力が変わると先頭の行を選ぶ。Tab は入力欄から出さない。IME の変換中の Enter では選ばない。開いている間は背後（外枠と本文）を操作できなくし、ほかの画面のキー（Mod+J・Mod+[ などの骨組みのキー、ノートの Mod+Shift+H など）を受け付けない。入力欄の編集のキー（Mod+V・Mod+Z など）はそのまま効く。背後にフォーカスが落ちたときも、Esc は閉じ、ほかのキーは入力欄へ戻すだけにする。

区分：一般（日付の切り替わり時刻、凪メーターの時間帯（始業・終業）、言語、更新の自動確認）、表示（テーマ、フォントサイズ、ノートの書体（本文と同じ／等幅。デザインガイド 4章）、レイアウト）、操作（ショートカット割当、Vimモード、持ち越し見直しの回数）、データ（保存先、バックアップ、書き出し）、エージェント（接続したエージェントと権限（切り替え・登録の整理）、ローカル API、変更履歴 S-06 を開く）、連携（将来・有料）、ライセンス（サポーターライセンスの入力）、このアプリについて（版、ライセンス、サードパーティライセンス）。

画面の細部（2026-11-05 決定。YUN-81。コードは `src/agents/`（`Agents.svelte` が画面、`AgentList.svelte` が権限の一覧。設定のエージェント区分と共通）、状態と操作は `src/lib/agents.svelte.ts`（一覧・取り消し・確認済み）と `src/lib/agent_admin.svelte.ts`（権限）、文言は `src/lib/i18n_agents.ts`、コマンドは `list_changes`・`preview_revert`・`revert_change`・`mark_changes_seen`と、権限の `list_agents`・`set_agent_scopes`。コマンドの中身は CLI・MCP 仕様書 7.4）：

- 絞り込み：エージェント（すべて／登録のあるエージェント）と「未確認のみ」。変えると先頭から読み直す。絞り込んだエージェントの登録がなくなっていたら、絞り込みを外して読み直す。
- 確認済み：開いただけでは付けない（上部のバーの件数と整理モードの行頭の ◆ が、見ていない間に消えないように）。未確認の行に「確認済みにする」を置き、押した行だけに付ける。「表示中をすべて確認済みにする」は、表示している未確認の記録すべて（読み込んでいない記録は含めない）に付ける。画面が実際に見せた記録の ID だけをコアに送る（一覧を読んでから届いた変更を、見せずに確認済みにしないため）。付けたら、上部のバー・サイドバーの件数と、整理モードの ◆ が読み直される。取り消すと、その記録は自動で確認済みになる（CLI・MCP 仕様書 7.3）。
- 取り消し：行の「取り消す」を押すと、まだ保存していない入力を送り終えてから、取り消す内容を読み（`preview_revert`）、その行の下に確かめる文を広げる（別のダイアログは重ねない）。内容は記録の種類による：項目の欄は「欄・いまの値・戻す値」の表、項目の追加は「その項目を削除します」（持ち越し先があればそれは残ることも書く）、ノート・振り返りは「なくなる行（-）」と「戻る行（+）」の差分（共通の先頭と末尾の行は除く。200 行を超えたら途中までと書く）。ボタンは「取り消す」と「やめる」で、確かめる文を出したとき初めにフォーカスを置くのは「やめる」（Enter の二度押しで、確かめずに確定しないため）。
  - 人が記録のあとに変えた欄があれば（`changed_since`）、その欄を強調し、「記録のあとに「本文」が変更されています。上書きすると、その変更が失われます。」と書く。このときは通常の「取り消す」を出さず、「上書きして取り消す」だけを出す（見せた値で上書きする。`force`）。
  - 取り消すときは、見せた内容の目印（`token`）を送る。見せた後に内容が変わっていたら（`conflict`・`changed`・`afterPreview`）、書かずに「確認したあとに内容が変わりました。もう一度、取り消す内容を確かめてください。」を出して、取り消す内容を読み直す。
  - すでに戻っている記録（`already_restored`）は、「すでに記録の前の値に戻っています。値は書かず、取り消し済みの印だけを付けます。」と書き、「取り消し済みにする」で印だけを付ける。すでに取り消し済み（`already_reverted`）なら、その旨だけを出す。
  - 取り消せない理由は、取り消す内容の代わりに出し、何も変えない：項目が持ち越し済み（持ち越し先の日付を添えて、持ち越し先の項目を直すよう案内する）、取りやめた TODO、対象の項目が削除された・記録が置き換わった（一覧を読み直す）、いま入力中（入力を終えてから行う）、保存できていない入力がある（保存できてから行う）、取り消しの記録・読み取れない記録。
  - 結果（「取り消しました。」「すでに戻っていたため、取り消し済みの印だけを付けました。」）は、一覧の上に出す（読み上げにも伝える）。取り消しの後、コアが `changed` を出し、整理モード・ノートの本文と件数は読み直される（ノートは、入力中でなければ差分として取り込まれる。アーキテクチャ設計書 4.1）。
- 読み込みの失敗：一覧を読めなかったときは「変更履歴を読めませんでした。」を出して、読み直す（前の内容は出したまま）。
- 見た目・実機の確認（フォーカスの動き、長い一覧のスクロール、差分の表示）は、テスト計画書（08）の実機の項目（YUN-87）で行う。

### 10.1 S-09 起動時の画面（2026-11-03 決定）

データベースを開くまでの間（アーキテクチャ設計書 4.3「起動」）、外枠（サイドバー・上部のバーなど）の代わりに窓全体に出す。開けたら整理モード（S-01）に進む。コアから届く状態と理由ごとに、何が起きたか・データが無事か・次にすることを示す。コードは `src/startup/`（操作は `src/lib/startup.svelte.ts`、入れ直し方と問い合わせ先の URL は `src/lib/support.ts`）。

- 設定の読み込み（2026-11-04 決定）：設定はデータベースにあるので（データモデル設計書 3章 setting）、この画面は保存したテーマ・言語・フォントサイズを使えない。テーマは OS に合わせ、言語は OS の言語（7章）、フォントサイズは既定（15px）で出す。データベースを開けたら、外枠を出す前に設定を読んで当てる（7章）。
- 共通：上にロゴ、見出し（状態が変わると見出しへフォーカスを移し、読み上げで伝える）、説明の文、場所（パスは等幅で、選んで写せる）、操作の並び。操作はどれもボタンで、キーボードだけで行える。行っている間はほかの操作を押せなくし、押したボタンを「処理しています」にする。失敗したら、そのボタンの下に `--warn` の文で理由を出す（コアのエラーの種類から決める。内部の文は出さない）。ただし、始める前に止まったとき（`not_ready`。状態が変わってボタンの欄が消えることがある）は「始める前に止まりました（ほかの処理がデータを使っているなど）。今の状態は上のとおりです。」、前のデータベースを元の場所に戻せなかったとき（`put_back_failed`）は残した場所と、ファイルを動かさずに知らせることを、見出しの下に出し、問い合わせ先を添える。やり直す・選び直す・戻すの後は、同じ状態に戻っても、バックアップの一覧を読み直す（同期でバックアップが届いた、使えなかったものが消えたなど）。戻せなかった理由は、読み直した一覧が空・読めなくても消さない。
- 開いている途中：「データを開いています」だけを `--text-muted` で出す。1 秒を超えたら「CLI・MCP がデータを使っているときは、終わるまで最大 5 秒待ちます。」を添える（ロックを待っているか、画面からは見分けられないため）。
- 見つからない（アーキテクチャ設計書 6.3）：見出し「データベースが見つかりません」、探した `yunagi.db` のパス、保存先を変えているときは記録した `config.json`、保存先のフォルダが無いときは「外付けのドライブを繋いでいないか、同期がまだ終わっていない」、あるときは「同期がまだ終わっていないか、ファイルが動かされた。空のデータベースは作らずに止めている」。続けて次の4つを、上から勧める順に並べる。
  1. 待ってからやり直す：「やり直す」（`retry_open`）。
  2. 保存先を選び直す：データベースのあるフォルダのパスを入れて「このフォルダを使う」（`choose_data_dir`）。中身を確かめてから記録し、データは移さないことを書く。パスの入力欄の隣に「フォルダを選ぶ」を置き、OS のフォルダ選択（Tauri のダイアログのプラグイン。`src/lib/folder.ts`。設定画面 S-05 の保存先・書き出し先と同じもの）で選んだパスを入力欄に入れる（記録は「このフォルダを使う」で行う。2026-11-04 決定。取りやめたら入力は変えない）。
  3. バックアップから戻す：`backups/` の一覧（新しいものから。種類「定期 11.02 Mon」「更新前（スキーマ 2 → 3）」「復元前」と、作った日時 `2026.11.02 09:12`）から1つ選んで「選んだバックアップから戻す」（`restore_at_startup`）。いちばん新しいものを最初から選んでおく。無ければ「使えるバックアップがありません。」。
  4. 新しく作る：後から元のデータが届いても自動ではまとまらないことを書き、押すと「空のデータで始めます。よろしいですか？」と「作る」「やめる」を出す（取り違えで空のデータを作らないよう、2段にする）。
- 開けなかった：理由（アーキテクチャ設計書 4.3）ごとに見出しと説明を出し、分かる場所（データベース・更新前のバックアップ・設定ファイル）を示す。最後に「詳しい情報（問い合わせのときに添える内容）」を閉じた状態で置き、開くと今の版とログ用の文（英語）を写せる形で出す。
  - マイグレーションの失敗（`migration_failed`）：「更新後の準備に失敗しました」。データの形を変える処理が途中で失敗し、更新前の状態に戻したこと、データは無事なこと。前の版の入れ直し方（ビルド・配布手順書 5章。OS に合わせて `curl -fsSL https://getyunagi.com/install.sh | YUNAGI_VERSION=<版> sh`、Windows は `$env:YUNAGI_VERSION="<版>"; irm https://getyunagi.com/install.ps1 | iex`。今の版も添える）、問い合わせ先。やり直しても同じなので「やり直す」は出さない。
  - 新しい版で作られたデータ（`unsupported_schema`）：「このデータは新しい版の Yunagi で作られています」。この版では読めないのでデータに触れていないこと、データは無事なこと。前の版ではなく、データを作った版か新しい版を入れる案内（`YUNAGI_VERSION` を付けないコマンドで最新を入れる）、問い合わせ先。旧版を入れ直したときや、新しい版を使う別の端末と同期したときに起きるため。
  - マイグレーションの失敗を戻せなかった（`migration_restore_failed`）：「更新後の準備に失敗し、元に戻せませんでした」。更新前のデータが残っているバックアップの場所を示し、ファイルを動かさずに問い合わせ先へ知らせることを書く（自動では直せないため、操作は出さない）。
  - 壊れている（`corrupted`）：「データベースが壊れているため、開けませんでした」。データベースには触れていないこと。上の「バックアップから戻す」（今のデータベースは消さずに `backups/` に残すことを書く。アーキテクチャ設計書 6.2「開けないデータベースからの回復」）、更新の直後なら前の版ではそのまま開けることがあるという入れ直し方、問い合わせ先。
  - ロックが取れない（`lock_busy`）：「ほかの処理がデータを使っています」。CLI・MCP の操作を 5 秒待ったこと。「やり直す」。
  - 既定ディレクトリ・ロックのファイルを使えない（`default_dir`・`lock`）、`config.json` が壊れている（`config`。設定ファイルの場所を示し、別の場所に空のデータを作らないよう止めていることを書く）、そのほか（`storage`）：理由の説明、「やり直す」、問い合わせ先。
  - 新しく作る場所にデータがある（`already_exists`）：上書きしないため止めたこと。「やり直す」（そこにあるデータを開く）。
- バックアップから戻した後（コアの状態が「戻した」の間。アーキテクチャ設計書 4.3）：「バックアップから戻しました」、バックアップを作った時点の内容になっていること、それまでのデータベースを残した場所（`backups/damaged-<秒>.db`）を示し、「続ける」（`acknowledge_restore`）で整理モードへ進む（場所を確かめる前に画面が変わらないように。状態はコアが持つので、画面を読み込み直しても同じものを出す）。
- 問い合わせ先は、サポート・障害対応手順 1章の窓口（公開リポジトリの GitHub Issues と、アカウントが無い場合のメール）。公式サイトは `https://getyunagi.com`、公開リポジトリの Issues は `https://github.com/misty-swan/yunagi/issues`、メールは `support@getyunagi.com`（2026-11-06 決定。YUN-11 で実際の値にした）。`src/lib/support.ts` の1か所にまとめ、画面は空かどうかを見ずにそのまま出す。

- 見た目（余白、配色、文字、罫線）は試作品を参考にし、確定した値はデザインガイド（06）に書き戻す。
- 試作品は次の順で作る：S-01 整理モード（3種のレイアウト、ライト・ダーク）、S-02 ノートモード、S-03 持ち越し、S-04 検索パレット、S-08 ふりかえり。S-05〜S-07 は後回しでよい。
