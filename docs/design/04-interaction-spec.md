# 操作仕様書（ショートカット・IME・Vimモード）

## 1. 表記

- `Mod`：macOS は ⌘、Windows・Linux は Ctrl。
- 割当は設定（操作 → ショートカット割当）で変更できる。以下は初期値（案）。本書をショートカットの正本とし、要件定義書 7章は代表的な割当のみを載せる。変えられる操作と決まり（2026-11-04 決定。`src/lib/keymap.ts`）は、次の「割当の変更」。
- 割当の変更（2026-11-04 決定。値は setting の `shortcuts`。データモデル設計書 3章）：
  - 変えられる操作：2章の表のうち、画面が受けているもの。共通（ノートモード ⇄ 整理モード・前日／翌日へ移動（ふりかえりでは週の移動）・今日へ戻る・検索パレット・設定・サイドバー・ふりかえり）、整理（領域の移動・完了／解消の切替・項目の上下移動・項目の削除）、振り返り（テンプレートの挿入）、ノート（TODO／障害へ送る・時刻付き見出し）。前日・翌日の割当を変えると、ふりかえりの週の移動も同じ割当になる。
  - 変えられない操作：取り消し・やり直し（Mod+Z・Mod+Shift+Z・Windows・Linux の Ctrl+Y。エディタの履歴と整理モードのリストの履歴が同じキーを受けるため）、Enter（項目の追加・行の分割）、Esc・矢印・Space など、画面ごとの移動と決定のキー（ふりかえり・持ち越し・検索パレットの中のキー。1章の範囲）、Vim のキー（4章）。Yunagi を前面に呼び出す（Mod+Shift+D）と依頼文の書き出し（Mod+Shift+A）は、まだ作っていないので、いまは割り当てを予約するだけ（ほかの操作に割り当てられない）。作るときに、割当を変えられる操作に加える。
  - 割当の書き方：修飾キーを `+` でつなぎ、最後にキー。修飾キーは `Mod`・`Alt`・`Shift`（書くときはこの順にそろえる）。キーは、英字 A〜Z・数字 0〜9（キーの位置で判定）、記号 `[ ] \ , . / ; ' - = `` ` ``（押した文字で判定）、`Enter`・`Backspace`・`Delete`・`Tab`・`Space`・矢印。割当の文字列の判定は、上のキーの判定の決まりのとおり。
  - 割り当てられないキー（設定に出す理由つきで断る）：Mod も Alt も付かないキー（文字の入力と区別できない）、macOS の Option だけの文字・記号のキー（Option は文字を打つ）、macOS の Option と記号のキー、記号のキーと Shift（配列で打つ文字が変わる）、Windows・Linux の Ctrl と Alt の組み合わせ（AltGr で文字を打つ配列がある）、Mod+C・V・X・A、取り消し・やり直しのキー、Mod+Shift+D・Mod+Shift+A、Vimモードが有効な Windows・Linux の Ctrl+[（Esc と重なる）。
  - 衝突：効く範囲（共通・整理（一覧と振り返り）・ノート）が重なる操作が、同じキーを使う割当は断る。共通は、すべての範囲と重なる。整理とノートは重ならない（同じキーにできる）。断るときは、ほかの操作の割当を外さず入れ替えもせず、使っている操作の名前を示す（先にそちらを変えてもらう）。
  - 初期割当と同じキーにしたときは、割当を持たない（初期割当に従う）。「初期値に戻す」も同じ。
  - 設定を後から変えて重なったときの扱い（Vimモードの有無で初期割当が変わるとき、設定ファイルを直接書き換えたとき）：変えた割当が初期割当に勝ち、初期割当の側の操作は使えなくなる（設定画面にその旨を出し、キーの案内には出さない）。変えた割当どうしが重なれば、設定画面の並びの先の操作が勝つ。読めない割当・割り当てられないキーの割当は、無視して初期割当にする（設定画面にその旨を出す）。
  - 割当は、保存したらすぐ画面のキーとキーの案内（上部のバー・サイドバー・パレット・キーの案内・ノートの行のメニュー）に当たる。キーを押し続けたときの繰り返しの扱い（共通の画面の操作は動かさない）は、割当を変えても同じ。
- キーの判定（2026-11-03 決定。割当を変えられるようにした後も同じ。`src/lib/keymap.ts` の `matches`）：文字のキー（J・T・K・L など）はキーの位置で判定し、配列によらず同じ位置のキーで動く。記号のキー（`[` `]` `\` `,` など）は押した文字で判定する（JIS 配列では位置が US 配列とずれるため）。macOS で記号を Option と打つ配列でも動くよう、macOS の記号のキーでは Option を問わない。Windows・Linux では、Ctrl と Alt が同時に付いたキー（AltGr は Ctrl+Alt として届く）はショートカットとして扱わない（AltGr で `[` などを打つ文字の入力を妨げないため）。Alt だけの割当（Vimモード有効時の Alt+[ / Alt+] など）は、Alt の有無を割当に合わせて照合する。代わりに、押した文字が当たらないときは US 配列の記号のキーの位置（`[` `]` `\` `,` の位置）でも受け、記号を単独のキーで打てない配列（ドイツ語の配列など）でも動くようにする。JIS 配列の macOS で `\` のキーが打つ `¥` も Mod+\\ として扱う。共通の画面の操作（Mod+J・Mod+[ / Mod+]・Mod+T・Mod+\\ など）は、キーを押し続けたときの繰り返しでは動かさない。
- 範囲：「OS全体」はアプリが前面になくても有効、「共通」はアプリ内のすべての画面で有効、「整理」「ノート」は各モード中のみ、「振り返り」は振り返り欄の編集中のみ、「ふりかえり」はふりかえり（Archive）画面（S-08）の表示中のみ有効。「持ち越し」は持ち越しの画面（S-03）の表示中のみ有効で、その間は「共通」のキーも受け付けない（画面設計書 5章）。

## 2. 標準ショートカット

| 操作 | 初期割当 | 範囲 |
| --- | --- | --- |
| Yunagi を前面に呼び出す | Mod+Shift+D | OS全体 |
| ノートモード ⇄ 整理モード | Mod+J | 共通 |
| 前日・翌日へ移動 | Mod+[ / Mod+] | 共通（ふりかえりでは週の移動） |
| 今日へ戻る | Mod+T | 共通 |
| 検索パレット | Mod+K | 共通 |
| 設定 | Mod+, | 共通 |
| サイドバーを開く・閉じる | Mod+\\ | 共通 |
| ふりかえり（Archive）を開く・閉じる | Mod+Shift+L | 共通 |
| 日を選ぶ／その日を開く／戻る | ← → ／ Enter ／ Esc | ふりかえり |
| 週を移動 | Mod+[ / Mod+]（Vimモード有効時の Windows・Linux は Alt+[ / Alt+]。4.1） | ふりかえり（ほかの画面では前日・翌日） |
| 今日を選ぶ | Mod+T | ふりかえり（ほかの画面では今日へ戻る。Mod+J は、ふりかえりでは受けない。画面設計書 9章） |
| 行の移動／チェックの切替／選んだものを持ち越す／後回し | j/k・↑/↓ ／ Space ／ Enter ／ Esc | 持ち越し |
| 行の移動／選ぶ／閉じる | ↑/↓ ／ Enter ／ Esc・Mod+K | 検索パレット（画面設計書 6章） |
| 直前の操作を取り消す | Mod+Z | 共通 |
| やり直す | Mod+Shift+Z（Windows・Linux は Ctrl+Y も可） | 共通 |
| 領域の移動（TODO／障害／振り返り） | Mod+1 / 2 / 3 | 整理 |
| 新しい項目を追加 | Enter（行末で） | 整理 |
| 項目の完了・解消の切替 | Mod+Enter | 整理 |
| 項目の上下移動 | Alt+↑ / Alt+↓ | 整理 |
| 項目の削除 | Mod+Backspace | 整理 |
| 振り返りテンプレートの挿入 | Mod+Shift+R | 振り返り |
| 現在行を TODO へ送る | Mod+Shift+T | ノート |
| 現在行を障害へ送る | Mod+Shift+B | ノート |
| 時刻付き見出しの挿入 | Mod+Shift+H | ノート |
| 選んだ TODO をエージェント向け依頼文として書き出す | Mod+Shift+A | 整理 |

複数行を選択した状態で「TODO へ送る」を実行した場合は、各行を1件ずつ送る。

試作品（ブラウザで動作）では、ブラウザのキーとの衝突を避けるため、Mod+\\ と Mod+Shift+L の代わりに Alt+\\、Alt+Shift+L を使う（画面設計書 12章）。

- 取り消し・やり直し：エディタ内では文字編集の取り消し、整理モードのリストでは項目の追加・削除・完了・並べ替えの取り消しとする。エージェントによる変更は対象外とし、変更履歴（S-06）から取り消す。
  - 持ち越しの確定（持ち越しの画面 S-03 の3つのボタン。画面設計書 5章）は、Mod+Z・Mod+Shift+Z の対象にしない（2026-11-04 決定）。確定は、今日への項目の作成、前回の日の項目の取りやめ（`dropped`）、分割の子の作成、「今日の持ち越しを終えた」記録を、日をまたいで1回で行う。まとめて戻すと、確定の後の完了・本文の編集・削除・次の日の持ち越し・エージェントの操作と食い違い、取りやめた項目だけを戻しても子や記録が残るため。確定の前に、画面で行ごとにチェックと見直しの選択を確かめられるので、取り消しの代わりにはそれを使う。確定の後に直したいときは、通常の操作で直す：持ち越した項目や分割の子の削除は、これまでどおり Mod+Z で戻せる（ただし、持ち越し先の削除は、元の項目が削除の後に変わっていたときは戻せない。データモデル設計書 3章 item）。「やめる」「分割する」で取りやめた項目を未完了に戻すことはできないので、必要なら今日に新しい TODO を足す（取りやめた TODO は過去の日の記録として残す。データモデル設計書 3章）。
  - 確定は履歴に加えず、消しもしない。確定の前に行った操作（同じ日の項目の追加・削除・完了・並べ替え）は、確定の後も Mod+Z で戻せる（確定が加えた項目は、その操作の対象にならない）。確定は同じ日のボードの読み直しなので履歴は残り、確定が加えた項目は履歴と無関係に並んだまま、確定の前の操作だけが戻る（行の位置は、戻す操作の対象の項目を基準にする）。確定によって履歴が捨てられることは無い（履歴が空になるのは、別の日のボードを読んだときと、上限を超えて古いものから捨てるとき、戻した分を使い切ったときである）（今日の初回表示の持ち越しは、たいてい履歴が空のときに出る）。持ち越しの画面を出している間は、Mod+Z を受け付けない（1章の「持ち越し」の範囲の決まり）。
  - 整理モードのリストの細部（2026-11-03 決定。`src/lib/board.svelte.ts`）：項目の本文の入力と行の分割も取り消せる。本文の入力は、同じ行で続けて入力する間（別の行へ移るか、ほかの操作をするまで）を1回の取り消しにまとめる。行の分割の取り消しは、分けた2行の本文をつなぎ直して1行に戻す。解消メモの入力は取り消しの対象にしない（その欄の文字の取り消しはしない）。取り消す時点で、その項目の本文・状態がその操作の後の値でなければ（その後にエージェントが変えていれば）、その記録は飛ばして、1つ前の記録を取り消す。取り消しの履歴は表示している日ごとに持ち、日を移ると捨てる（最大 200 件）。
- 一覧の編集（整理モード）：
  - ↑ / ↓ で項目間を移動する。折り返した項目では、先頭の行で ↑、末尾の行で ↓ を押したときに隣の項目へ移る。
  - 行の途中の Enter で、カーソル位置で2件に分ける。行頭の Enter で直上に項目を追加する。
  - 空の項目で Backspace を押すと、その項目を削除して直前の項目へ移る。何も書かずに離れた項目は消す。
  - 細部（2026-11-03 決定）：行の途中の Enter で、カーソルより前が空白だけなら直上に、後ろが空白だけなら直下に、空の項目を足す（分けない。データモデル設計書 3章「行の分割」）。持ち越し済みの項目と取りやめた TODO では、行の途中でも分けずに直下に足す。本文を消して離れた（空白だけになった）作成済みの項目は、削除として扱い、Mod+Z で戻せる（消している途中の本文は保存せず、消し始める前の本文で戻る）。Mod+Backspace で削除したら次の項目へ（無ければ直前の項目、それも無ければ領域へ）移る。項目の本文に貼り付けた改行は空白にする。Mod+1 / 2 で移る先は、その領域で最後に選んでいた項目、無ければ最初の未完了・未解消の項目、それも無ければ最初の項目（項目が無ければ領域）。
  - マウスのドラッグ（5章）は、本文・チェック欄・印の外をつかんで動かし、同じ種類の中でだけ並べ替える。動かす位置は、Alt+↑ / Alt+↓ と同じく、送る時点の画面の並びで決める（アーキテクチャ設計書 4.1「自動保存」）。
  - 項目の追加とその直後の入力は、1回の取り消しで戻る。
  - 障害を解消すると、その場で解消メモを入力できる。Enter・Esc で確定する。
  - 過去の日のボードで、持ち越し済みの項目（次の日以降へ持ち越した元の項目。扱いの正本はデータモデル設計書 3章）は、完了・解消の切替（Mod+Enter・x・チェック欄のクリック）、本文と解消メモの編集を受け付けない（2026-11-03 決定）。操作しようとしたときは、上部のバーに「11.03 Tue へ持ち越し済みです」と短時間表示する。Mod+Z もこの項目の状態・本文を戻さない。削除と並べ替えは通常どおりできる（削除した持ち越し先を Mod+Z で戻せない場合はデータモデル設計書 3章）。持ち越し先の項目は、行末の印（画面設計書 3章）から開ける。
  - 過去の日のボードで、取りやめた TODO（`dropped`。画面設計書 3章）は、完了・未完了の切替（Mod+Enter・x・チェック欄のクリック）と、本文を変える操作（下の「本文を変える操作の範囲」。行の途中の Enter は分けずに直下に足す）を受け付けない（2026-11-03 決定。扱いの正本はデータモデル設計書 3章）。操作しようとしたときは、上部のバーに「持ち越しの見直しで閉じた TODO は変更できません」（英語：This TODO was closed in the carry-over review and can't be changed）と短時間表示する（「やめた」「分割した」のどちらにも当たる文言にする）。Mod+Z でも、取りやめた後のこの項目の状態・本文を変えない（持ち越しの見直しの確定そのものは Mod+Z で取り消せない。上の「取り消し・やり直し」）。削除と並べ替えは通常どおりできる。エージェントからの `edit_todo`・`complete_todo`・`reopen_todo` も受け付けない（MCP・CLI 仕様書 3章）。
  - 本文を変える操作の範囲（2026-11-04 決定。`src/board/ItemRow.svelte`、`src/lib/board.svelte.ts` の `lockOf`）：持ち越し済みの項目と取りやめた TODO（以下「閉じた項目」）は、次の操作を受け付けない。受け付けないとは、項目の本文・状態・解消メモ・完了時刻を変えず、保存も送らず、上部のバーに上の2つの文の合う方を短時間表示することをいう。閉じた項目の本文は入力欄にせず、読み取り専用で表示する（文字の入力・IME の変換を始められない）。
    - 受け付けない操作（知らせる）：
      1. 文字の入力と削除：文字を打つキー（Shift 付きの大文字、macOS の Option・AltGr で打つ文字、Space を含む。Windows・Linux の Alt+文字はメニューなどのキーなので対象にしない）、Backspace、Delete（Option などとの組み合わせも）。IME の変換も同じ（本文が入力欄でないので始まらない）。
      2. 貼り付け・切り取り・文のドロップ（Mod+V・Mod+X は、キーとクリップボードのイベントのどちらでも知らせる。ほかのアプリや行の本文からの、文・URL・ファイルのドラッグ。項目の並べ替えのドラッグは対象外で、受け付ける）。
      3. 完了・解消の切替（Mod+Enter・x・チェック欄のクリック）。
      4. 解消メモの編集（解消済みの障害を持ち越したときの元の項目。メモの文を押しても入力欄を開かない）。取りやめた TODO に解消メモは無い。
      5. Vim モード（4章）の編集の操作：整理モードのリスト（4.3）の `i` `a`（編集を始める）と `x`（切替）。項目の本文に入って行う編集（`cc` `cw` `dw` `p` `>` など。4.2 の編集は、ノート・振り返りのエディタだけの操作で、項目の本文には無い）は、本文の入力欄に入れないので起こらない。
    - 受け付ける操作（知らせない）：削除（Mod+Backspace・`dd`）、並べ替え（Alt+↑ / ↓・`J` / `K`・ドラッグ）、項目間の移動、領域の移動、選択、本文のコピー（Mod+C）、持ち越し先を開く操作、「← NOTE」を開く操作。
    - 受け付けるが本文を変えないもの：閉じた項目での Enter は、行のどこでも（本文はカーソルを置けない読み取り専用なので、位置を問わない）分けずに、直下に空の項目を足す（知らせない。足した項目は通常の項目）。Vim の `o` `O` も同じく、足すだけで本文を変えない。Mod+Z・Mod+Shift+Z（`u` を含む）は、受け付けて履歴を動かすが、閉じた項目の本文・状態は戻さず、その記録は飛ばす（上の「取り消し・やり直し」）。
    - エージェントの書き込みの扱いは MCP・CLI 仕様書 3章。ノート・振り返りは項目ではないので、過去の日でも通常どおり編集できる。
  - 解消済みの障害を未解消に戻しても（Mod+Enter・x・チェック欄のクリック）、解消メモは消さずに残す（2026-11-03 決定）。誤って戻しただけで利用者の記録が黙って消えないようにするため。未解消の間は解消メモを表示しない（画面設計書 3章。解消メモは解消済みの障害の下に出す）。もう一度解消すると、残っていた解消メモを表示し、その場で入力できる欄にカーソルを末尾に置いて開く。消したい場合は、その欄で消す。解消時刻は、未解消に戻すと空にし、もう一度解消した時刻を入れ直す。ただし Mod+Z で未解消に戻す操作を取り消した場合は、新しい時刻を入れず、戻す前の解消時刻に戻す（解消メモの欄も開かない）。未解消に戻した後にエージェントがその障害の状態を変えていた場合は、Mod+Z はその項目の状態を戻さない（エージェントの変更は Mod+Z の対象外で、変更履歴から取り消す。上の「取り消し・やり直し」）。解消メモを入力中に未解消に戻した場合は、まだ保存していない入力をすぐに書き込んでから欄を閉じ、その時点で入力中を終える（アーキテクチャ設計書 4.1）。持ち越しで次の日に作る障害には、残っている解消メモを写さない（元の日の障害に残る。データモデル設計書 3章）。TODO の完了も同じく、画面で未完了に戻すと完了時刻を空にし、Mod+Z で取り消した場合は元の完了時刻に戻す（その後にエージェントが状態を変えていた場合は戻さない）。エージェントからの扱いは MCP・CLI 仕様書 3章。
- ノートの編集：
  - 「- 」で始まる行の Enter で、次の行も「- 」で始める。中身のない「- 」の行の Enter は「- 」を消す。

## 3. IME（日本語入力）の扱い

1. IME の変換中（composition 中）は、Enter・Esc・修飾キーとの組み合わせをショートカットとして扱わない。変換確定の Enter で項目が追加されることがあってはならない。
2. Enter・Esc・修飾キー付きの keydown は、`event.isComposing` が true、または `event.keyCode === 229` の場合はショートカットとして扱わない。さらに WebKit 系（macOS・Linux）では `compositionend` の直後に届く最初の Enter keydown を確定操作とみなして無視する（同一イベントループ内の判定とし、ミリ秒単位の時間しきい値は使わない）。
3. 3 OS それぞれで、主要な IME（macOS：日本語入力、Google 日本語入力／Windows：Microsoft IME、Google 日本語入力／Linux：fcitx5-mozc、IBus-mozc）での動作をテスト計画に含める。

## 4. Vimモード

### 4.1 全般

- 既定は無効。設定（操作 → Vimモード）で有効にする。
- 完全な Vim 互換は目指さず、日常的な操作に絞る。`:w` などの保存系コマンドは自動保存のため不要とする。
- Mod キーを使う標準ショートカットは、Vimモード中もそのまま使える。ただし Windows・Linux の「前日・翌日へ移動」と、ふりかえり（S-08）の「週を移動」のみ例外とする（下記）。
- 現在のモード（NORMAL / INSERT / VISUAL）は、エディタ右下に小さく表示する。
- Windows・Linux では Ctrl+[ が Vim の Esc と重なるため、Vimモード有効時は「前日・翌日へ移動」の初期割当を Alt+[ / Alt+] に変更する。ふりかえりの「週を移動」も同じく Alt+[ / Alt+] にする。
  - 細部（2026-11-04 決定）：「初期割当を変更する」とは、割当を変えていない操作の割当が Vimモードの有無に従うことをいう（割当を変えた操作は、Vimモードの有無で変わらない。1章「割当の変更」）。ふりかえりの週の移動は、前日・翌日の移動と同じ操作として受ける（`src/shell/AppShell.svelte` の `prevDay`・`nextDay`）ので、同じ割当に従う。macOS の ⌘[ は Esc と重ならないので変えない。Vimモードが有効な Windows・Linux では、Ctrl+[ をショートカットに割り当てられず、整理モードのリストの挿入モードを抜けるキー（Esc と同じ）として受ける。
  - 実装の範囲（2026-11-04 決定）：整理モードのリスト（4.3）は、設定のVimモードに従って動く。ノート・振り返りのエディタ（4.2）と、モードの表示、IME との両立（4.4）は、まだ作っていない（Vimモードが有効でも、ノート・振り返りのエディタは通常どおり動く）。エディタの Vim は CodeMirror の Vim 拡張（アーキテクチャ設計書 2章）で作る。

### 4.2 ノートと振り返り（エディタ）

| 区分 | 対応する操作 |
| --- | --- |
| モード | ノーマル、挿入（i a I A o O）、ビジュアル（v V） |
| 移動 | h j k l、w b e、0 ^ $、gg G、{ }、f t、数字による回数指定 |
| 編集 | x、dd、dw などのオペレータ＋モーション、cc、cw、yy、p P、u、Ctrl+R、. 、> < |
| 検索 | / ? n N |
| Yunagi 固有（ノートのみ） | `<Space>t` 現在行（ビジュアル時は選択行）を TODO へ送る、`<Space>b` 障害へ送る、`<Space>h` 時刻付き見出しの挿入 |

振り返り欄では `<Space>t` / `<Space>b` / `<Space>h` は何もしない。

### 4.3 整理モード（リスト）

| キー | 動作 |
| --- | --- |
| j / k | 項目間の移動 |
| gg / G | 先頭・末尾へ |
| o / O | 直下・直上に新規追加して挿入モード |
| i / a | 選択中の項目を編集（挿入モード）。i は行頭から、a は行末から |
| x | 完了・解消の切替 |
| dd | 削除（取り消し可） |
| J / K | 項目を下・上へ移動 |
| u | 直前の操作を取り消す |
| Tab / Shift+Tab | 領域の移動 |
| Esc | 編集を終えてノーマルモードへ |

細部（2026-11-04 決定。`src/board/ItemRow.svelte` の `onVimKey`、`src/lib/board.svelte.ts` の `insert`・`vimPending`）：

- ノーマルモードは、行を選ぶだけで、項目の本文を入力欄にしない（クリックは選ぶだけ。5章）。挿入モードの間だけ、整理モードのすべての項目の本文が入力欄になる（モードは行ごとでなく整理モード全体で1つ。↑ / ↓・Enter・Backspace などは通常どおり働く）。Vimモードが有効でも、Mod を使う標準のショートカット（2章）はノーマルモードでも使える。
- j / k は項目間（同じ領域の中）を移り、端では動かない。gg / G は領域の先頭・末尾へ。Tab / Shift+Tab は TODO → 障害 → 振り返りの順に領域を移る（端から反対の端へ回る）。振り返りの欄はエディタ（4.2）で、まだ Vim のキーで操作できない。
- o / O は、選択中の項目の直下・直上に空の項目を足して、挿入モードに入る。足すだけで本文を変えないので、持ち越し済みの項目と取りやめた TODO でも使える。何も書かずに離れた項目は、通常どおり消える。
- i / a は、選択中の項目の本文を行頭・行末から編集する（挿入モード）。x は完了・解消の切替（障害を解消したら、解消メモの欄を開く）。持ち越し済みの項目と取りやめた TODO では、i / a / x は本文・状態を変えず、挿入モードにも入らず、上部のバーに知らせる（2章「本文を変える操作の範囲」）。
- dd は削除（直後の項目を選ぶ。Mod+Z で戻せる）、J / K は項目の下・上への並べ替え、u は直前の操作の取り消し（Mod+Z と同じ）。g と d は、続きのキーを待つ。続きでないキーが来たら、待っていたキーは捨てて、そのキーを通常どおり扱う。
- ノーマルモードで、Enter・文字・Backspace・Delete のうち上の操作に当たらないものは、何も起こさず、知らせない（本文を入力欄にしていないので、入力にならない）。ノーマルモードの Enter は項目を分けない（足すのは o / O）。数字による回数指定（`3j` など）と Ctrl+R（やり直し。2章の Mod+Shift+Z を使う）は、整理モードのリストでは受けない。
- 挿入モードは Esc（Windows・Linux は Ctrl+[ も）で抜け、選択中の項目を保ったままノーマルモードに戻る。日本語入力の変換中の Esc は、変換の取り消しなので抜けない（3章）。Vimモードを無効にすると、本文はふたたび常に入力欄になる。
- ダブルクリックは挿入モードで編集を始める（行末にカーソル。変えられない項目では知らせる）。

### 4.4 IME との両立

1. 挿入モードからノーマルモードに戻ったとき（Esc、Ctrl+[）、IME を自動で英数入力に切り替える。
2. ノーマルモード中は、IME の状態にかかわらずキー入力を Vim の操作として扱う（IME に入力を渡さない）。
3. 挿入モードに入ったときは、直前に挿入モードを抜けた時点の入力状態に戻す（設定で無効化可能）。
4. Linux で IME の切替ができない環境では、2 のみを保証し、設定画面に制約を表示する。

## 5. マウス操作（補助）

- Vimモード無効時は、項目のクリックでその位置にカーソルを置く（選択と編集を兼ねる）。
- Vimモード有効時は、項目のクリックで選択、ダブルクリックで編集。
- どちらでも、行頭のチェック欄のクリックで完了・解消を切り替える。
- 項目のドラッグで並べ替え。
- ノートの行の右クリックメニューから「TODO へ送る」「障害へ送る」。
  - 細部（2026-11-03 決定。`src/note/NoteView.svelte`）：選択範囲の外で右クリックしたら、カーソルをその位置へ移してから、押した位置にメニューを重ねて出す（選択範囲の中なら、選択範囲の行を送る。窓の右・下の端の近くでは、窓の中に収まるよう寄せる）。メニューの項目には、同じ操作のキー（Mod+Shift+T・B）を添える。開くと最初の項目にフォーカスを置き、↑ / ↓ で項目を移り、Enter（またはクリック）で送ってエディタに戻る。Esc でエディタに戻って閉じ、メニューの外を押す・アプリが前面から外れる・ノートモードを離れると閉じる。送る行と送った後の知らせはキーで送るときと同じ（2章「ノートの編集」）。その日のノートを読み終えるまでは開かない。
