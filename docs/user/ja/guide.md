# Yunagi 利用者ガイド

Yunagi は PC の画面を「今日の仕事ノート1枚」として使うアプリです。今日やること、仕事を止めているもの、1日の振り返りだけを、日付ごとに整理します。

このガイドの **Mod** は macOS では ⌘ キー、Windows・Linux では Ctrl キーのことです。

## 1. インストールと更新

### インストール

#### macOS・Linux

```sh
curl -fsSL https://getyunagi.com/install.sh | sh
```

#### Windows（PowerShell）

```powershell
irm https://getyunagi.com/install.ps1 | iex
```

#### 安全に入れるために

スクリプトの中身を確認してから実行したい場合は、URL を開いて内容を読み、保存したファイルを実行してください。インストールスクリプトは公開されている SHA-256 ハッシュで配布物を自動で照合します。配布物を手動で入手した場合は、公式サイトの `SHA256SUMS` とその署名 `SHA256SUMS.sig`（minisign）で照合してください。手順は公式サイトの「配布物の確かめ方」のページにあります。

#### 入る場所

インストールスクリプトで入れると、ログインしている利用者だけが使う形で入ります（管理者の権限は要りません）。

- macOS：`~/Applications/Yunagi.app`。コマンドの `yunagi` は `~/.local/bin/yunagi` にリンクされます。
- Linux：`~/.local/opt/yunagi/`（アプリの AppImage とコマンド）。コマンドは `~/.local/bin/yunagi` にリンクされ、アプリ一覧に Yunagi が加わります。
- Windows：`%LOCALAPPDATA%\Programs\Yunagi`。スタートメニューに Yunagi が加わり、`bin` フォルダがユーザーの `PATH` に加わります。

`~/.local/bin` が `PATH` に入っていないときは、インストールスクリプトが追記の方法を案内します。ノートのデータはアプリの置き場所とは別の場所に保存されるので（7章）、入れ直してもデータは残ります。

### 更新

- 新しい版は起動時と、その後24時間ごとに確認します。新しい版があると、サイドバーの下端に「New version」が出ます（サイドバーを閉じているときは、上部のバーの右側です）。
- 「New version」を選ぶと更新内容が出るので、「更新して再起動」を押します。Mod+K の検索・コマンドから「更新して再起動」を選んでも同じです。作業中に勝手に再起動することはありません。再起動する前に、入力中の内容を保存します。
- 更新に失敗したときは、何も入れ替えずに「更新できませんでした」と出ます。そのまま使い続けられ、もう一度試せます。
- 更新でデータの形式が変わるときは、新しい版が最初にデータを開く前に、Yunagi がバックアップを作ります。データの変換に失敗したときは、自動でバックアップに戻してデータを変えず、旧版の入れ直し方を案内します。
- 確認をやめたいときは、設定の「General」区分の「更新の自動確認」を無効にします。無効にすると、Yunagi はこの確認の通信をしません。
- Linux で tar.gz または .deb から導入した場合、アプリ内の自動更新は使えません。新しい版は同じ方法で入れ直してください（AppImage はアプリ内で自動更新されます）。

特定の版を入れたいとき（旧版に戻すときなど）は、環境変数 `YUNAGI_VERSION` に版を指定して、インストールスクリプトを実行します。

```sh
curl -fsSL https://getyunagi.com/install.sh | YUNAGI_VERSION=1.2.3 sh   # macOS・Linux
```

```powershell
$env:YUNAGI_VERSION="1.2.3"; irm https://getyunagi.com/install.ps1 | iex   # Windows
```

## 2. 最初の起動

インストール後、アプリ一覧から Yunagi を起動します。以後は **Mod+Alt+Y**（macOS は ⌘⌥Y。Windows・Linux は Mod を使わず、Alt+Shift+Y）で、どのアプリからでも呼び出せます。

このキーは設定の「Operation」区分の「ショートカット割当」で変えられます（英字か数字のキーに、Mod か Alt を組み合わせます）。ほかのアプリが同じキーを使っていて OS に登録できないときは、設定のその行の下に理由が出ます。別のキーに変えてください。

Linux の Wayland 環境では、このショートカットが効かないことがあります（設定にもその旨が出ます）。その場合は、デスクトップ環境のキーボード設定で、コマンド `yunagi show` を好きなキーに割り当ててください。

- GNOME：「設定」→「キーボード」→「キーボードショートカット」→「カスタムショートカット」で追加します。
- KDE Plasma：「システム設定」→「キーボード」→「ショートカット」→「カスタムショートカットを追加」で追加します。
- Hyprland・Sway など：設定ファイルのキー割当（`bind`）に、`yunagi show` を実行する行を足します。

  ```
  # Hyprland（~/.config/hypr/hyprland.conf）
  bind = SUPER SHIFT, D, exec, ~/.local/bin/yunagi show
  # Sway（~/.config/sway/config）
  bindsym $mod+Shift+d exec ~/.local/bin/yunagi show
  ```

`yunagi show` は Yunagi の窓を前面に出します（最小化を解き、隠れていれば表示し、フォーカスを移します）。Yunagi が動いていなければ、起動してから出します。起動して窓が出るまで、数秒かかることがあります。

- キーに割り当てたコマンドが見つからないと言われるときは、そのキー設定がふだんのシェルの `PATH` を引き継いでいません。`~/.local/bin/yunagi show` のように、置いてある場所を含めた名前（上の例のとおり）で書いてください。`~` が使えない設定では、自分のホームフォルダの実際のパスに置き換えます。
- ノートモードで開きたいときは、別のキーに `yunagi show --note` を割り当てます（会議中にすぐメモを取るためなど）。
- コマンドの結果はターミナルから `yunagi show` を実行して確かめられます。Yunagi が見つからないときは、環境変数 `YUNAGI_APP` に Yunagi の場所を設定します。

## 3. 1日の使い方

Yunagi には、2つの画面（モード）があります。TODO・障害・振り返りを並べて整理する**整理モード**（画面では Board）と、その日のメモを全面に書く**ノートモード**（Note）です。**Mod+J** で切り替えます。

1. **朝**：新しい日に最初に開くと、前回使った日にやり残した TODO と、まだ解消していない障害が「CARRY OVER」の画面に並びます。開いたときは全部にチェックが付いているので、今日は続けないもののチェックを外し、「選んだものを持ち越す」「すべて持ち越す」「持ち越さない」のどれかを押します。3回以上（回数は設定で変更できます）持ち越している TODO には「分割する／やめる」の選択肢が出ます。考え直すきっかけにしてください。今は決めたくないときは Esc で後回しにできます（次に Yunagi を前面に出したとき、もう一度だけ出ます。Mod+K の「持ち越しを開く」からも開けます）。持ち越しを確定したあとは、Mod+Z では取り消せません。
2. **日中**：整理モードで TODO を上から順に片付けます。並び順がそのまま優先度です。行末で Enter を押すと新しい項目を足せ、Mod+Enter で完了、Mod+Shift+Backspace で削除です（Mod+Z で戻せます）。仕事を止めているものがあれば、障害・詰まり（Blockers）に書きます。Mod+1・Mod+2・Mod+3 で、TODO・障害・振り返りの欄を移れます。
3. **会議中**：**Mod+J** でノートモードに切り替え、自由にメモを取ります。**Mod+Shift+H** で「10:00 定例」のような見出しを入れると、会議ごとに区切れます。
4. **会議の後**：やるべきことになった行で **Mod+Shift+T**（TODO へ）、困りごとの行で **Mod+Shift+B**（障害へ）を押して送ります。もう一度 **Mod+J** で整理モードに戻ります。
5. **終業時**：振り返り欄に、良かったこと、詰まったこと、明日の一手を書きます（**Mod+Shift+R** で見出しを挿入）。

保存は自動です。保存ボタンはありません。保存できないときは、上部のバーに「保存できていません」と出ます。入力した内容は画面に残り、自動で保存をやり直します。

画面上部の「凪メーター」はその日の様子を空と海の景色で表します。太陽はいまの時刻（既定では 9:00〜19:00 の間を進みます。設定の「General」区分の「凪メーターの時間帯」で変更できます）を、波は残りの仕事を、海面の光の道は終えた仕事を表します。残りが0件になると波が平らになり、「NAGI」と表示されます。

左側のサイドバーには、Today（今日。残りの件数つき）、Archive（ふりかえり）、Agents（エージェントによる変更の履歴。確認していない変更の件数つき）、Recent（直近の日の一覧）、Settings（設定）があります。**Mod+\\** で開閉でき、ノートモードでは自動で閉じます。

過去の日を見返すときは、**Mod+Shift+L** でふりかえり（Archive）を開きます。1週間（月〜金）の各日の様子と、記録のある直近の日の振り返り（良かったこと・詰まったこと）、選んだ日の振り返りとノートの見出しが並びます。← → で日を選び、**Mod+[ ／ Mod+]** で週を移動し、Enter でその日を開きます。Esc（または **Mod+Shift+L**）で元の画面に戻ります。

**Mod+K** の検索・コマンドでは、すべての日の TODO・障害・ノート・振り返りを検索できます。「2026-10-31」や「昨日」のような日付を入れると、その日へ移動します。設定を開く、レイアウトを変えるなどのコマンドもここから呼べます。

### 表示の設定

設定の「Display」区分で、テーマ（OS に合わせる／ライト／ダーク）、フォントサイズ、ノートの書体（本文と同じ／等幅）、レイアウトを選べます。レイアウトは A（左に TODO、右上に障害、右下に振り返り）、B（3列）、C（縦積み）の3種類です。ウィンドウの幅が 900px より狭いときは、設定にかかわらず C で表示します。表示の言語は「General」区分の「言語」で日本語と English から選べます。

## 4. 主なショートカット

| 操作 | キー |
| --- | --- |
| Yunagi を呼び出す | Mod+Alt+Y（Windows・Linux は Alt+Shift+Y） |
| ノートモード ⇄ 整理モード | Mod+J |
| 行を TODO へ／障害へ送る | Mod+Shift+T ／ Mod+Shift+B |
| 時刻付きの見出しを入れる（ノート） | Mod+Shift+H |
| 振り返りの見出しを入れる | Mod+Shift+R |
| TODO・障害・振り返りの欄を移る | Mod+1 ／ Mod+2 ／ Mod+3 |
| 完了・解消の切替 | Mod+Enter |
| 項目の削除 | Mod+Shift+Backspace |
| 選んだ TODO を依頼文としてコピー | Mod+Shift+A |
| 項目の並べ替え | Alt+↑ ／ Alt+↓ |
| 前日・翌日 ／ 今日へ戻る | Mod+[ ／ Mod+] ／ Mod+T |
| 取り消し ／ やり直し | Mod+Z ／ Mod+Shift+Z（Windows・Linux は Ctrl+Y も可） |
| 検索・コマンド | Mod+K |
| サイドバーの開閉 | Mod+\\ |
| ふりかえり（Archive） | Mod+Shift+L |
| 設定 | Mod+, |

macOS では Alt は Option キーです。画面の下端には、いま使える主なキーが出ます。

ここに載せたキーのうち、取り消し・やり直し以外は設定の「Operation」区分の「ショートカット割当」で確認・変更できます（同じ範囲の別の操作と同じキーにはできません。取り消し・やり直し、コピー・貼り付けのキーは変えられません）。

## 5. Vimモード

設定の「Operation」区分の「Vim モード」で有効にできます。ノートと振り返りではノーマル・挿入・ビジュアルの各モードが使えます。ノートでは `<Space>t` で TODO へ、`<Space>b` で障害へ行を送り（ビジュアルモードでは選んだ行を送ります）、`<Space>h` で時刻付きの見出しを入れて続けて件名を書けます。振り返りでは `<Space>` のキーは何もしません。今のモードはエディタの右下に小さく出ます。

整理モードでは j / k で移動、`]]` / `[[` で次・前の領域（TODO → 障害 → 振り返り。Tab / Shift+Tab でも同じ）へ移動、o で追加、i で編集、x で完了・解消の切替、dd で削除、u で取り消しです。振り返りの中でも、ノーマルモードの `]]` / `[[` で領域を移れます（Vim のセクション移動は使えません）。

日本語入力がオンのままだと `]]` / `[[` は効かないので、英数に切り替えてください。挿入モードから戻ると、日本語入力は自動で英数に切り替わります（挿入モードに入ったときに、前に挿入モードを抜けた時点の日本語入力の状態へ戻すかどうかは、設定の「挿入モードで入力状態を戻す」で選べます）。Linux で fcitx5 も IBus も動いていない環境では、日本語入力を自動で切り替えられません。そのときは設定に注意が出るので、挿入モードを抜けたら日本語入力を手で英数に切り替えてください。

Windows・Linux で Vimモードを有効にすると、前日・翌日への移動（ふりかえりでは週の移動）は **Alt+[ ／ Alt+]** に変わります（Ctrl+[ が Vim の Esc と重なるため）。ショートカット割当を自分で変えたものは、Vimモードを切り替えても変わりません。

また、Windows・Linux では Ctrl を使う Vim のキー（Ctrl+V、Ctrl+A、Ctrl+X、Ctrl+D など）は Vim の操作にならず、取り消し（Ctrl+Z）やコピー・貼り付けなど、いつものショートカットのままです（やり直しの Ctrl+R と Esc の代わりの Ctrl+[ だけは Vim の操作です）。

## 6. Claude Code・Codex と連携する

```sh
yunagi agent setup
```

を実行すると、Claude Code と Codex に Yunagi が登録されます。ターミナルで実行すると、書き込む内容が表示され、確認（`y`）のあとで書き込みます（元の設定ファイルは、隣にコピーを残してから変更します。端末でない所からは実行できません）。最初はエージェントは読み取りしかできません。TODO の追加などを任せたい場合は、設定の「Agents」区分で権限を有効にしてください。エージェントが行った変更には印が付き、変更履歴（サイドバーの Agents）から1件ずつ取り消せます。

ターミナルからは次のコマンドで確かめられます。権限の変更と取り消しは、変更内容が表示され、確認（`y`）のあとで確定します（端末でない所からは実行できません）。

```sh
yunagi agent permissions                              # エージェントごとの権限を見る
yunagi agent permissions claude-code --allow todo     # 権限を足す（--deny で外す）
yunagi agent history                                  # エージェントの変更を新しい順に見る（* は未確認）
yunagi agent revert <変更のID> [--force]               # 1件取り消す
```

取り消しはその変更が変えた部分だけを元に戻します。あとから自分で同じ部分を変えていたときは、取り消さずに止まります（差分を確かめて `--force` を付けると、その部分を上書きします）。持ち越し済みの項目や、やめた TODO は、状態や本文を変えた変更を取り消せません（その日の終わりの状態として残すためです。足した項目を消す取り消しはできます）。

エージェントが Yunagi から読んだ内容は、そのエージェントを通じて各AIサービスに送られます。取り扱いは利用者と各AIサービスとの契約に従います。AIの利用料は各サービスの契約に含まれ、Yunagi の連携機能は無料です。

シェルから直接使うこともできます。CLI からの書き込みも最初は許可されていません。書き込みたい場合は、設定の「Agents」区分で `cli` の権限を有効にしてください（権限の変更は、アプリの設定画面か、ターミナルでの確認でしか確定できません）。

```sh
yunagi todo add "レビューのコメントに返信"
yunagi board get
git log -1 --format=%s | yunagi reflection append -
```

コマンドの一覧は `yunagi --help` で見られます。

### エージェントへの依頼文

整理モードで TODO を選んで **Mod+Shift+A** を押すと、その TODO をエージェントに頼むための文章（Markdown）がクリップボードにコピーされます。依頼文には TODO の本文が入ります。その TODO をノートの行から送った場合は、元の行がある時刻付き見出しの区間のメモと、同じ区間から送った未解消の障害も入ります。エージェントの入力欄にそのまま貼り付けてください。依頼文にはノートの内容が入るので、貼り付ける先を確かめてからお使いください。

ターミナルからは `yunagi handoff export <TODO の ID>` で同じ文章を表示します（ID は `yunagi board get` で分かります）。エージェントからは、読み取りの権限があれば `export_handoff` で取得できます。

## 7. データについて

- Yunagi がデータを外部に送ることはありません。データはこの PC の保存先に保存されます（エージェントが読んだ内容の扱いは6章のとおりです）。
- 新しい版の確認のため、Yunagi は起動時などに版・OS・アーキテクチャだけを送ります（配布元には IP アドレスと日時が記録されます）。設定の「General」区分で無効にできます。
- サポーターライセンスのキーを確かめるときは、キーを入力して確かめる操作をしたときにだけ（1回の操作につき1回）、販売サービスに、キーと Yunagi の販売元を示す固定の識別子を送ります（販売サービスには IP アドレスと日時が記録されることがあります）。ノートなどのデータは送りません。キーを入力しなければ、この通信はありません（キーの入力は、今後の版で使えるようになります）。
- 保存先は設定の「Data」区分で確認・変更できます。直近7日分のバックアップが自動で作成され、同じ区分の一覧から復元できます。更新の前と復元の前のバックアップは、それぞれ新しい3つを残します。
- 保存先を iCloud Drive や Dropbox などのフォルダにする場合は、同時に1台の PC だけで開いてください。複数の PC で使うときは、Markdown の書き出しやバックアップを同期する方法をおすすめします。
- 1日分や期間を Markdown で書き出せます。設定の「Data」区分で、開始日・終了日と書き出し先のフォルダを選んで「書き出す」を押すと、日付ごとのファイルができます。

## 8. アンインストール

```sh
yunagi uninstall          # アプリと CLI を削除（データは残ります）
yunagi uninstall --purge  # データも削除
```

`--purge` で消えるのは、次のものです。

- ノートのデータ（既定の保存先のフォルダ。設定で保存先を変えているときは、その保存先の `yunagi.db` とバックアップ）
- 画面の表示のために Yunagi が作ったキャッシュなど（OS ごとの場所は、`io.github.misty-swan.yunagi` という名前のフォルダやファイル。Linux・Windows は1つのフォルダ、macOS は `~/Library` の下の数か所）

保存先のフォルダそのものは、ほかのファイルがあるかもしれないので消しません。Yunagi が動いているときは、何も消さずに止まります。先に Yunagi を終了してください。

消す前に、消すものを一覧にして `[y/N]` と確認します。自分で端末から実行してください（スクリプトや AI エージェントのシェルからは動きません）。終わると、消したものと、消せなかったものを理由つきで一覧にします（消せなかったものは手で消してください。このときは 0 以外の終了コードで終わります）。Windows では、最後の後片付け（インストールしたフォルダと、`--purge` のときはデータのフォルダ）が、コマンドが終わった直後にバックグラウンドで動きます。しばらくして残っていたら、手で消してください。

この PC への入れ方が分からないとき（手で置いた、開発用のビルド、tar.gz など）は、見つけた場所を示して何も消さずに止まります。設定ファイル（`config.json`）が壊れているときも、保存先が分からないので、何も消さずに止まります。
