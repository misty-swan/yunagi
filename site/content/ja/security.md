# セキュリティ

Yunagi は利用者の業務メモを扱うため、データを端末の外に出さないことを基本にしています。保護の仕組みの全文は公開リポジトリの[セキュリティ方針](https://github.com/misty-swan/yunagi/blob/main/docs/release/SECURITY.md)にあります。

## 脆弱性の報告

- **公開の Issue には書かないでください。**
- 報告先は次のどちらかです。
  - メール：[security@getyunagi.com](mailto:security@getyunagi.com)
  - 公開リポジトリの「Security」タブ →「Report a vulnerability」（GitHub の非公開の報告）
- 影響を受ける版（`yunagi --version`）、OS、再現の手順、何が起きるかを書いてください。業務ノートなどの実際のデータは貼らないでください。
- 受領の連絡は 3営業日以内、初期評価の結果は10営業日以内に返すことを目標にしています（約束ではありません）。
- 修正版を公開したあと、報告者の同意があれば、謝辞を載せます。

## サポートする版

セキュリティ修正は最新のマイナー版（たとえば 1.4.x）のパッチ版として出します。それより古いマイナー版には出しません。更新をご案内します。

## 配布物の保護

- インストールスクリプトは配布物の SHA-256 を照合し、一致しなければ中止します。
- 全配布物のハッシュをまとめた `SHA256SUMS` には配布用の鍵で minisign の署名を付けています。手順は[配布物の確かめ方](/ja/verify/)にあります。
- アプリの自動更新は Yunagi 独自の鍵で署名したパッケージだけを、署名を検証してから適用します。
- Yunagi は OS の有料のコード署名を使っていません。そのかわりに、上の方法で配布物が公式のものであることを確かめられるようにしています。

## データ

- データは利用者のデータディレクトリにだけ保存します。ディレクトリとデータベースは利用者本人だけが読み書きできる権限で作ります。
- 外部との通信は更新の確認（既定で有効。設定で無効にできます）、サポーターライセンスのキーの確認、利用者が有効にした機能に限ります。更新の確認で送る情報は版・OS・アーキテクチャだけです。キーの確認は、キーを入力して確かめる操作をしたときだけ（1回の操作につき1回）で、送る情報はキーと、Yunagi の販売元を示す固定の識別子だけです（キーの入力は、今後の版で使えるようになります）。
- AI エージェントの権限は既定で読み取りだけです。書き込みは利用者が許可した範囲だけで、変更はすべて記録され、1件ずつ取り消せます。

## 告知

セキュリティ修正と鍵の失効は、[お知らせ](/ja/news/)と、公開リポジトリの GitHub Security Advisory で告知します。
